# @venizia/vulcan-okf

Generator, conformance gate, coverage report and graph explorer for a project's knowledge bundle at
`.agents/knowledge/`, in the [Open Knowledge Format (OKF)](https://github.com/GoogleCloudPlatform/open-knowledge-format)
v0.2. Part of VULCAN; the bundle is served over MCP by `@venizia/vulcan-atlas`, not from here.

## Commands

Run through the pinned `vulcan` CLI (`bun x vulcan x okf <command>`) or the project's make targets.
The tooling reads the project it runs in (the working directory).

| Command | What it does |
|---|---|
| `check` | Gate: OKF v0.2 conformance (spec §11). Errors fail; soft-guidance warnings print and never fail |
| `check --strict` | `check` plus the house rules: every link resolves, docs style, structural coverage, freshness |
| `gen` | Regenerate all source-derived content |
| `coverage [--min <n>]` | Report the bundle against the source inventory; `--min` fails below `<n>` percent |
| `viz` | Build the offline graph explorer, `.agents/knowledge/viz.html` |

## OKF v0.2 conformance (`check`)

Exactly the spec, never stricter:

- Every non-reserved `.md` file has a parseable YAML frontmatter block with a non-empty top-level `type` (§11.1, §11.2).
- `index.md` carries no frontmatter; the bundle-root one may carry `okf_version` alone (§8, §12).
- `log.md` date headings open with a real `YYYY-MM-DD`, newest first (§9). Text after the date is tolerated - the spec is silent on it.
- Never rejected (§11): unknown types, unknown keys, missing optional fields, broken links, missing `index.md`.
- Warnings (soft guidance): `status` outside draft/stable/deprecated (§5.4), timestamps that are not ISO 8601 datetimes with an offset (§5), a `sources` entry without `resource` (§5.1), actors that are not `<producer>/<version>`, `human:<id>` or `process:<id>` (§7), an older `okf_version` (§12).

Links are bundle-absolute (`/x.md`, recommended) or relative (`./x.md`, `../x.md`, `x.md`), anchors
allowed; links inside code are examples, never edges. Files may use LF or CRLF line endings.

## What is generated vs hand-authored

Two mechanisms, both driven from source. Never hand-edit either.

1. **Whole generated files** - the `RENDERERS` registry in `okf.ts` writes `reference/*.md`, each
   with `generated.by: process:okf-gen` (§5.2). No `generated.at`: a timestamp would make every
   regeneration look like a change.
2. **Managed regions** - the `REGIONS` registry replaces content between
   `<!-- okf:generated:<id> start -->` and `<!-- okf:generated:<id> end -->` inside an otherwise
   hand-authored file.

`reference/public-surface.md`, `symbols.json` and `releases.json` are generated by
`@venizia/vulcan-atlas` (`vulcan x atlas surface|symbols|releases gen`), not by `gen`.

## Adding a renderer

1. Write a `collect*` function that extracts the fact from source.
   **Use it for both the renderer and the coverage counter** - a second heuristic for the same fact
   drifts, and the numbers disagree.
2. Write a `render*` returning `{ path, content }` and add it to `RENDERERS`.
3. Run `gen`, then `check --strict` twice: it must pass and be idempotent.

The renderers and coverage rows are IGNIS-specific today (`src/config.ts`); making them project
config is planned.

## Layout

| Path | Role |
|---|---|
| `src/cli.ts` | `vulcan-okf` entry |
| `src/okf.ts` | gen, check, coverage; renderers |
| `src/lib.ts` | bundle loader: frontmatter, links, concept model |
| `src/spec/` | OKF v0.2 conformance - pure, never throws |
| `src/viz/` | explorer: builder (Bun), typed browser client, template |
| `src/config.ts` | the only project-specific file: paths, section order, explorer copy |
