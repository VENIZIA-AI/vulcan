# cli - `@venizia/vulcan`

| Command | What it does |
|---|---|
| `init` | Scaffold the project layer; never overwrites. Writes `.configs/vulcan.config.mts`, appends the agent entries to `.gitignore`, installs the lint tools it configures, ends with a numbered list of what is left |
| `init --preset` | Create a new monorepo with its first app from a framework preset (`packages/cli/src/create/`); refuses a folder that is not empty |
| `add --preset` | Add an app from a preset to a monorepo `init --preset` created |
| `sync` | Write the gitignored agent adapters; takes back what the config no longer asks for; prints the base rules added, changed or removed since the manifest last recorded them |
| `doctor` | Check the project contract; exit 1 on any violation |
| `upgrade` | Install the target (`--stable`: `latest`, the default; `--nightly`: the higher of `latest` and `next`; a named version wins), then sync with the newly installed CLI |
| `x <okf\|atlas>` | Run a shipped tool at the pinned version, on the inherited stdio |

`@venizia/vulcan` depends on okf and atlas at the exact same version.

## Presets, `init --preset` and `add`

A preset is a framework's app template: `preset.json` plus a `files/` folder, found through `vulcan.presets.app` (and `vulcan.presets.lib` for a library kind) in the framework's `package.json`; the keys before 0.3.10 (`vulcan.preset`, `vulcan.lib`) are refused with the new shape named, no fallback. It is data only; VULCAN never runs code from it, and `presetVersion` is `1`.

- A name asked in a terminal or taken from a flag; none has a default (`--project`, `--backend-dir` or `--frontend-dir`, `--app`, `--shared-dir`). A bare `--preset <name>` means `@venizia/<name>`; `file:<path>` is for tests.
- `files/` is copied with `{{project}}`, `{{app}}`, `{{devPort}}` and `{{apiUrl}}` replaced; only `_gitignore`, `_npmrc`, `_env` and `_env.example` are written as dotfiles (npm drops dotfiles); binary files are copied byte for byte, symlinks are skipped, and `vulcan.presets.app`, `files` and every `checks` entry are validated (inside the package, a key of `scripts`).
- The config keeps `layout`, `packages` and the preset's `atlas` sources between the `vulcan:apps:start` and `vulcan:apps:end` comments. `add` rewrites only that block, and refuses with the lines to paste when the markers are gone.
- `add` keeps the catalog's versions over the preset's, refuses a preset whose `peers` the catalog does not satisfy, and picks the next free port from the apps' `.env.example`.
- `urls` (optional, paths starting with `/`) is what the closing `Next:` block opens, one `open http://localhost:<port><path>` per path; absent means the root. `init` records it in the app's `package.json` as `vulcan.urls`, so `add` prints every app's urls, and an app made before keeps the root. The block is `create/next.ts`. `add` without a terminal checks `--app`, the side folder and `--api`/`--no-api` before it downloads, as far as the flags name the side. The root `.gitignore` `init` writes ignores `*.tsbuildinfo`.
- `VULCAN_NO_INSTALL=1` (tests only) prints the install, `git init`, `sync` and the checks as `skipped` lines. An npm preset needs the install, so the tests use `file:` presets (`src/__tests__/fixtures/preset-*`). `VULCAN_BUN` and `VULCAN_GIT` (tests only) replace the `bun` and `git` executables, so a test can make an install or `git init` fail without the network.
- `doctor` has an `apps` check: every `layout` folder is a workspace and every package lives in one.

Wiki pages: `references/commands/init.md`, `references/commands/add.md` and `references/presets.md` under `docs/wiki/content/`.

## Prompts

Questions go through `packages/cli/src/ui` (wrappers over the pinned `@clack/prompts`), never clack directly. `menusAvailable()` (stdin and stdout TTY, `TERM` not `dumb`) picks menus; every other case keeps the plain line questions (`askWithPrompt`) so pipes and logs are unchanged. A pty test drives a menu with `driveTerminal` (`__tests__/terminal.helper.ts`); the older pty tests set `TERM=dumb` to keep covering the plain questions. Every prompt runs inside `guardAgainstPipedLines` (`ui/keyboard.ts`): a raw-mode keyboard sends CR for Enter, so the first LF while a menu is open means piped lines, and the command restores the terminal and exits 1 naming the flags and `TERM=dumb`.

## The shipped base (`packages/cli/base/`)

| Path | What it is |
|---|---|
| `rules.md` | the base rules, `V-W/S/P/B` (interim) plus IGNIS's coding style `V-C-01..18` |
| `slots.json` | base rules a project picks a wording for: `V-W-01` `on-user-word` or `read-only` (adds a git deny list) |
| `skills/` | `knowledge-sync` (with its Workflow script), `docs-writing`, `docs-update` and `build-a-feature` - project-neutral; skill evals have not been run against a model |
| `hooks/` | `session-start.ts` (rules digest) and `guard-writes.ts` (asks before `V-W-02`/`V-W-03` writes) and `guard-manifest.ts` (denies a Write/Edit/MultiEdit/NotebookEdit or a Bash redirect, `tee`, `sed -i`, `cp`/`mv` onto, or `rm` of `.agents/vulcan.manifest.json`) and `guard-package.ts` (denies a Write of a new `package.json` in a layout folder when a recorded preset makes that kind and gives the `vulcan add` command, else only a note) and `guard-git.ts` (parses the command with `hooks/shell.ts`; denies deleting or force-pushing `develop`/`main` and `gh pr merge --delete-branch` on a PR headed by one, asks on `reset --hard`, other force-pushes and `branch -D` of an unmerged branch) and `guard-outside.ts` (asks when a file, worktree, clone or temp file would land outside the project; allowlist of tool-owned stores plus `guard.toolOwnedPaths`; `VULCAN_GUARDS=off` kills both guards) and `subagent-start.ts` (injects the compact digest into every subagent) and `guard-remote-hosts.ts` (registered by sync only when the config sets `remoteHosts`: asks before a command reaches an unlisted host, also through HTTP clients to a readOnly host, a piped shell, a nested ssh or a loop body) |
| `owner/` | The report contract and the personal profile: `schema.ts` (the top-level `owner` config key, English and `advise` by default, and the strict profile schema), `profile.ts` (read, validate, write `.agents/local/profile.json`; a write refuses while `.gitignore` lacks `.agents/local/`, saves mode 0600), `view.ts` (`resolveOwnerView`: personal settings over the project block; the project's shape and status set are not overridable; `enforce` is the stricter of the two; a language with no label set gets English), `card.ts` (the two digest cards). The framework ships English only: any other language is the person's own label set. |
| `local/` | What an agent leaves under `.agents/local/`: `scan.ts` (`scanLocal`: every entry with size, age and state - stale by the layout's `staleAfterDays`, a worktree classified merged / gone / unmerged / orphan from `git worktree list` and `git branch --format=%(refname:short) --merged` - and `isInsideLocal`, which resolves the parent and never follows a final symlink), `clean.ts` (`planClean`, `runClean`: a registered worktree goes through `git worktree remove`, then prune; a symlink is unlinked; a path outside `.agents/local/` is refused), `format.ts`. `vulcan clean` and doctor's stale and size lines read it. |
| `base/skills/` | The shipped skills, linked into every project by `sync`: `build-a-feature`, `docs-update`, `docs-writing`, `knowledge-sync` and the agent-work set `plan-a-change` (lanes S/M/L, the spec card, the design pass), `fix-a-bug` (the loop first), `review-a-change` (independent, axes kept apart), `report-back` (done, status, preview, handoff; the owner reply shape is read from the digest, never restated), `ship` (done checklist, PR body, public-state probes, approval before a shared action), `retro` (classify before proposing, evidence-tied, nothing applied without a pick), `research` (read-only, fetched content untrusted, clones in `.agents/local/clones/`) and `visualize-work`. Each has `evals/evals.json`; a test keeps every description to 50 words with a "Use when" part, the lint clean, and no project name. |
| `visualize/` and `commands/visualize.command.ts` | `vulcan visualize`: a strict zod spec (`schema.ts`, limits in `constants.ts`: 25 boxes, 40 arrows, 100 KB hard cap, 60 KB warning), cross-checks (`validate.ts`: unique ids, one box per cell, arrows and steps point at boxes), an inline-SVG figure on a grid (`layout.ts`), the page CSS and JS we author (`assets.ts`, no vendored library, text set only with `textContent`), `renderPage` (`page.ts`: every text escaped, a CSP meta that allows only the page's own style and script by sha256 hash, https-only links) and `render.ts` (size gate, `writePage` atomically into `.agents/local/prototypes/`, trusted `localRootOf` only). Page words are English; a `chrome` object in the spec replaces them. The command cannot see the page: a browser check is the caller's and is reported as run or not run. |
| `signals/`, `hooks/post-tool.ts` and `base/hooks/post-tool.ts` | The turn's notes: an append-only log (`.agents/local/cache/signals.jsonl`, one line per call, a turn marker per prompt, per session; parallel hooks lose nothing; a symlinked folder or file is never followed), `classify.ts` (public probes and gate commands found by parsing the command, not by matching text), `loopOf` (same call x3 within a minute, a-b-a-b for three rounds, three failures of one input), `checkClaims` (whole-word phrases in a sentence that does not deny, ask, quote or look ahead; a public claim with no probe, a completion claim while a gate's latest run failed; English plus `owner.report.claimWords`; logged only, never said back) and the post-tool hook (advisory, imports only `signals/` and the shell parser, fails open, about 10 ms). |
| `hooks/subagent-card.ts` and `base/hooks/subagent-start.ts` | The subagent's start context: a fixed card (`SUBAGENT_CARD`, about 250 tokens, a test holds it under `SUBAGENT_CARD_MAX_CHARACTERS` = 1,600) citing the base rules a subagent must keep. It carries neither the owner shape nor the profile, and the hook imports only the card (no config, no zod). |
| `owner/shape.ts`, `owner/violations.ts`, `hooks/owner-reply.ts` and `base/hooks/stop.ts`, `prompt-submit.ts` | The shape check: `checkOwnerShape` (pure; structural classes can block, style classes are only logged; a reply under the view's `shortReplyWords`, the lower of the project's and the person's, is exempt), the log `.agents/local/violations.jsonl` and the last-reply note, one file per session in `.agents/local/cache/replies/` (classes and dates only, never the text; trusted `.agents/local/` only, no symlinked file or folder; pruned by age and by count), `buildStopOutput` (record, and block once under `block`; a retry never blocks) and `buildPromptContract` (one line per prompt, naming the last reply's faults). Both hooks fail open. `doctor` prints the counts as a note. |
| `owner/survey.ts` and `commands/profile.command.ts` | The `vulcan profile` form: `runSurvey` takes an `ISurveyIo` (menus in a terminal, plain lines otherwise; an empty answer takes the default, the end of input cancels) and returns a profile that `writeProfile` saves; `offerProfile` is the once-only offer after `init` (a confirm in a terminal, a hint line elsewhere). |
| `base/references/` | Detail the skills share, one home each, named by their `node_modules/@venizia/vulcan/base/references/` path (skills are linked one by one, so a relative link between them would not resolve): `design-pass.md`, `testing.md`, `evidence.md`, `delegation-brief.md` (rule V-P-12), `phase-boundaries.md`. A test keeps the list, requires a contents list past 100 lines, and checks that every path a skill names exists. |
| `claude/settings.json` | shared Claude settings registering both hooks |
| `make/vulcan.mk` | shipped make targets, all through `bun x --no-install vulcan` |
| `templates/` | what `init` writes: AGENTS.md, rules.md, knowledge index (with the `vulcan:scaffold` marker), a Makefile (include plus a fallback rule), the config in four formats, the two lint configs, written to `.configs/lints/` (none in a workspaces project: each app keeps its own); the formatter has no config file, the `[fmt]` section of the root `bunfig.toml` is it |
