# Changelog - 2026-10-18

## VULCAN 0.2.0-8: atlas.packages removed, a concept lock that sees members, a self-explaining fresh clone

<Badge type="warning" text="Breaking Change" /> <Badge type="tip" text="New Feature" /> <Badge type="danger" text="Security" /> <Badge type="tip" text="Enhancement" /> <Badge type="info" text="Bug Fix" />

**In one line.** The root fixes before the stable 0.2.0: the one breaking removal, a stronger concept lock, and a fresh clone that says what to do.

## What changed

- **`atlas.packages` is removed.** The alias was kept through 0.2.0-7 and is removed in 0.2.0-8. A config that still sets it fails with `atlas.packages was removed - move the list to the top-level packages: [{ dir, name }]`.
- **`.symbols.lock.json` uses schemaVersion 2.** The lock now hashes the whole declaration instead of capping signatures at 300 characters. A lock from 0.2.0-7 or earlier stops `concepts check` with `run vulcan x atlas concepts stamp`.
- **`concepts check` locks the whole declaration.** A member added to an interface or class, or a parameter changed past the old 300-character signature cap, now fails the check. Comments and layout do not move the lock.
- **`doctor` says once that a clean checkout is not synced.** When gitignored adapters have never been written, it prints `not synced yet - run 'bun x --no-install vulcan sync' (make agent-setup) first` instead of one `stale (created)` line per file.
- **The Makefile `init` writes explains a missing `vulcan.mk`.** With no `node_modules`, a shipped target such as `okf-check-strict` stops with `run 'make install' (bun install) first` instead of `No rule to make target`. Targets the project defines (`install`) are untouched.
- **`init` writes `.mcp.json`.** When absent, `init` writes `.mcp.json` pointing to the atlas server with `--root .`. An existing file is not overwritten; one missing an `atlas` entry gets the entry printed as a hint.
- **`changes` offers declared packages.** Its `unknown package` message lists every declared package, released or not.
- **A bare `vulcan x atlas` at a terminal prints usage.** Stdin attached to a terminal prints usage text; stdin opened as a pipe still starts the MCP server.
- **A remote-host guard.** Set `remoteHosts: { trusted, readOnly }` and `sync` registers a hook that asks before a Bash command reaches an unlisted host across tools like ssh, scp, rsync, kubectl, and nc (including under `sudo`, `bash -c`, or `xargs`). Hosts match by exact name or a `*` pattern, never by substring.
- **`remoteHosts.localFile` supports uncommitted trusted hosts.** The guard supports `remoteHosts.localFile` (defaulting to `.agents/hooks/trusted-hosts.local`) for a gitignored personal list of trusted hosts; the policy is rendered into `.agents/vulcan.manifest.json`.
- **The `read-only` git slot covers the whole write surface.** `V-W-01: read-only` now denies 30 git verbs (40 deny entries), up from 14 verbs (17 entries): `add`, `rm`, `mv`, `restore`, `commit`, `push`, `pull`, `merge`, `rebase`, `reset`, `revert`, `cherry-pick`, `checkout`, `switch`, `branch`, `tag`, `stash`, `clean`, `apply`, `am`, `worktree`, `remote`, `config`, `submodule`, `update-ref`, `filter-branch`, `gc`, `init`, `clone`, `notes`. Because `git remote` and `git config` are denied whole, their read forms are denied too.
- **`okf.contents.files` takes globs.** Patterns like `.agents/skills/*/SKILL.md` are supported.
- **`okf.coverage` axes take `exclude` and `denylist`.** `exclude` accepts root-relative globs and `denylist` accepts directory names for that axis only. The top-level `okf.denylist` continues to apply across all axes. An axis left with no directories fails.
- **The guide drops fixed gaps.** The TypeScript auto-install note and the one-line concept lock are removed from Known gaps. Shipped skills are noted as not evaluated against a model.

## Who is affected

- **A project whose config sets `atlas.packages`.** Move the list to the top-level `packages` array.
- **A project whose concepts declare `symbols:`.** Run `vulcan x atlas concepts stamp` once to upgrade `.symbols.lock.json` to schemaVersion 2.
- **A project using git read-only for agents.** The deny list covers 30 verbs; `git remote` and `git config` are denied whole, so an agent cannot read them either; read that information another way, or run the command yourself.
- **A project that carries `overrides` for `@venizia/vulcan-okf` or `@venizia/vulcan-atlas`.** Drop them. `@venizia/vulcan` names sibling packages as `workspace:*` in the repository, and `bun publish` packs exact versions into tarballs. Every release check verifies the packed manifest.
- **Everyone else.** No action needed: upgrade, then run `vulcan sync`.

## Breaking changes

> [!WARNING]
> Projects configuring `atlas.packages` or locking symbols must update their configuration and stamp their lock file for schemaVersion 2.

**Before:**

```typescript
// vulcan.config.ts
atlas: {
  packages: {
    okf: '@venizia/vulcan-okf',
    cli: '@venizia/vulcan',
  },
},
```

**After:**

```typescript
// vulcan.config.ts
packages: [
  { dir: 'okf', name: '@venizia/vulcan-okf' },
  { dir: 'cli', name: '@venizia/vulcan' },
],
```

1. Move `atlas.packages` key-value pairs to the top-level `packages: [{ dir, name }]` array.
2. Run `vulcan x atlas concepts stamp` once to generate a schemaVersion 2 `.symbols.lock.json`, review the diff, and commit it.
