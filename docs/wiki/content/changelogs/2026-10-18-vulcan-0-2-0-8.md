# Changelog - 2026-10-18

## VULCAN 0.2.0-8: atlas.packages removed, a concept lock that sees members, a self-explaining fresh clone

<Badge type="warning" text="Breaking Change" /> <Badge type="tip" text="New Feature" /> <Badge type="danger" text="Security" /> <Badge type="tip" text="Enhancement" /> <Badge type="info" text="Bug Fix" />

**In one line.** The last fixes before the stable 0.2.0: one breaking removal, a stronger concept lock, a remote-host guard and a fresh clone that says what to do.

## What changed

- **`atlas.packages` is removed.** A config that still sets it fails with `atlas.packages was removed - move the list to the top-level packages: [{ dir, name }]`.
- **`concepts check` locks the whole declaration.** A member added to an interface or class, or a changed parameter, now fails the check; comments and layout do not. `.symbols.lock.json` moves to schemaVersion 2, and an older lock stops the check with `run vulcan x atlas concepts stamp`.
- **A remote-host guard.** Set `remoteHosts: { trusted, readOnly }` and `sync` registers a hook that asks before a Bash command reaches an unlisted host through ssh, scp, rsync, kubectl, nc and similar (also under `sudo`, `bash -c`, `xargs`). Hosts match by exact name or a `*` pattern. `remoteHosts.localFile` (default `.agents/hooks/trusted-hosts.local`) holds a gitignored personal list.
- **The `read-only` git slot covers the whole write surface.** `V-W-01: read-only` now denies 30 git verbs, up from 14, including `commit`, `push`, `reset`, `checkout`, `rebase`, `stash`, `config` and `remote`. `git remote` and `git config` are denied whole, so their read forms are denied too.
- **A fresh clone explains itself.** `doctor` says once `not synced yet - run 'bun x --no-install vulcan sync' (make agent-setup) first`; a shipped Makefile target without `node_modules` says `run 'make install' (bun install) first`; `init` writes `.mcp.json` when absent (an existing file is not overwritten).
- **More.** `changes` lists declared packages in its `unknown package` message, a bare `vulcan x atlas` at a terminal prints usage, `okf.contents.files` takes globs, and `okf.coverage` axes take `exclude` and `denylist`.

## Who is affected

- **A project whose config sets `atlas.packages`, or whose concepts declare `symbols:`.** Follow the steps below.
- **A project using git read-only for agents.** Read `git remote` and `git config` another way, or run them yourself.
- **A project with `overrides` for `@venizia/vulcan-okf` or `@venizia/vulcan-atlas`.** Drop them.
- **Everyone else.** No action needed: upgrade, then `vulcan sync`.

## Breaking changes

> [!WARNING]
> Projects configuring `atlas.packages` or locking symbols must update their configuration and stamp their lock file.

**Before:**

```typescript
// vulcan.config.ts
atlas: {
  packages: {
    okf: '@venizia/vulcan-okf',
    cli: '@venizia/vulcan',
  },
},
```

**After:**

```typescript
// vulcan.config.ts
packages: [
  { dir: 'okf', name: '@venizia/vulcan-okf' },
  { dir: 'cli', name: '@venizia/vulcan' },
],
```

1. Move the `atlas.packages` pairs to the top-level `packages: [{ dir, name }]` array.
2. Run `vulcan x atlas concepts stamp` once, review the diff of `.symbols.lock.json`, and commit it.
