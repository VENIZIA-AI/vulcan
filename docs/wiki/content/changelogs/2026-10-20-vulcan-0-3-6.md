# Changelog - 2026-10-20

## VULCAN 0.3.6: one script standard for every app

<Badge type="tip" text="Enhancement" />

**In one line.** Backend and frontend apps now share one set of `package.json` scripts, `init` wires the root `dev` script to it, and `doctor` tells you which app departs from it, without failing.

## What changed

- **The standard.** Every app carries `server:dev` (a frontend runs vite), `compile` (`bun .configs/builders/compile.ts`; a frontend runs `vite build --config .configs/builders/vite.config.mts`), `typecheck` (`bun check`), `lint` (`devz lint`), `lint:fix` (`devz lint --fix`), `test` (`bun test`) and `clean` (`devz clean`). The work lives in `.configs/builders/` or behind `devz`, and an app root holds only `.configs/`, `src/`, `package.json`, `tsconfig.json` and `.env.example`. `dev`, `start`, `build`, `rebuild`, `preview` and `server:prod` are retired; a domain extra such as `migrate:dev` is fine. A library package keeps Makefile targets instead: `build`, `typecheck`, `lint`, `lint-fix`, `test`, `clean`. The new base rule `V-B-05` states it ([Rules](/references/rules)).
- **The root `dev` script runs `server:dev`.** The root `package.json` that `init --preset` writes now has `"dev": "bun run --filter '*' server:dev"`. `make dev` still calls it and the Next block still prints `make dev`. An app without a `server:dev` script is skipped, not an error.
- **`doctor` notes departures.** For each app (a live package in the `layout.backend` or `layout.frontend` folder) it prints one `info` line naming the standard scripts it lacks and the legacy ones it carries. The line never changes the exit code or the final `vulcan doctor: OK`. See [doctor](/references/commands/doctor#scripts).
- **VULCAN's own repository follows the library side.** The root Makefile now has `typecheck` and `lint-fix` next to `build`, `lint`, `test` and `clean`, and no `package.json` script carries a legacy name.

## Who is affected

- **A project made by an earlier `init`.** Its root `dev` script still runs `dev` in every app, so nothing breaks. To adopt the standard, rename the app scripts and change the root script to `bun run --filter '*' server:dev`; `doctor` lists what is left.
- **A framework author.** A preset whose `scripts` use the seven names works with the new root script. A preset that still declares `dev` gets an app that the new root script skips, so rename `dev` to `server:dev`.
- **Everyone else.** Nothing to do.

## Details

- The base rules are now 39: `V-B-05` is the fifth build rule.
- The preset fixtures in the tests use the standard names.
