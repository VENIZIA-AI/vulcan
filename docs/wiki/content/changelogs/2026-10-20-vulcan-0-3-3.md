# Changelog - 2026-10-20

## VULCAN 0.3.3: init asks in order

<Badge type="info" text="Bug Fix" />

**In one line.** `vulcan init --preset <npm package>` in a terminal asks the project name, the side folder, the app name and the shared folder in that order, names the side in the app question, and no longer prints `bun add` between the questions.

## What changed

- **The questions are in order.** Before, a published preset asked the project, then the generic `Name of the first app` and the shared folder, then fetched the package, then the side folder. The side is known only once the package is read, so `init` now asks the project name, fetches the preset, and asks `Backend folder` (or `Frontend folder`), `Name of this backend app` and `Shared code folder`. A local `file:` preset already asked in this order.
- **The fetch is one line.** `init` and `add` print `Fetching preset <name>@<range> ...`. The output of `bun add` is kept and printed only when the fetch fails.
- **Without a terminal nothing changes.** A missing flag is still refused before the network is used.
- **The test suites leave `/tmp` clean.** Three test files left a temp directory per run; they remove it now (see [#196](https://github.com/VENIZIA-AI/vulcan/issues/196)).

## Who is affected

- **Anyone who runs `init --preset` or `add --preset` with a published preset in a terminal.** Nothing to do; the prompts read differently and the files are the same.
- **A script that read the `bun add` output from `init` or `add`.** It is not printed on success any more.
