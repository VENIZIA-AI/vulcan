# Changelog - 2026-11-07

## Rule V-C-20 asks for the instance to be declared before it is awaited on

<Badge type="info" text="Behavior Change" />

**In one line.** The base code rules gain `V-C-20`: `await new X({...}).method({...})` is not written; the instance gets a name first and the `await` goes on its own line.

## What changed

- **`V-C-20` in the base rules.** Write `const runner = new X({...});` and then `await runner.run({...});`. A constructor inside an awaited call chain hides the object that does the work: a reader cannot name it, a second call cannot reuse it, and a failure in the constructor reads like a failure in the method. A longer chain (`await new X().a().b()`) is the same defect, and tests and scripts are covered too.
- **`await new Promise(...)` is not this form.** The constructor call is the awaited value itself, and the promise needs no name.
- **Soft rule.** Review checks it; no lint rule ships with it yet. `vulcan sync` brings the wording into your project.

## Who is affected

- **Every project that adopts the base rules:** new code follows `V-C-20`. Nothing breaks, and no config changes.
