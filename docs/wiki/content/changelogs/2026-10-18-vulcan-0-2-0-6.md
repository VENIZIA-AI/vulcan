# Changelog - 2026-10-18

## typescript is never auto-installed, changes knows an unreleased package

<Badge type="info" text="Bug Fix" />

**In one line.** atlas stops Bun from auto-fetching typescript, and `changes` reports entries for declared packages that have no release on the current ref.

## What changed

- **atlas never auto-installs typescript.** In a directory with no `node_modules`, Bun answered a bare `require('typescript')` by fetching typescript over the network. atlas now searches for `node_modules/typescript` on disk - first from the project, then in atlas's own install - and installs nothing. If typescript is missing from both locations, atlas fails with `atlas: cannot find typescript (looked in <project> and in atlas's own install) - install it with \`bun add typescript\``.
- **`changes` answers for declared packages with no releases on the current ref.** When a declared package (by npm name, directory key, or alias) has no release on this ref, while another package served by the same server does, `changes` returns the dated entries whose frontmatter names the package, alongside a note: `no release of <package> is recorded on this ref`. Passing `from` or `to` versions for that package is refused with code `-32602`. Undeclared package names still return `unknown package`.
- **Accurate reason when a ref has no releases.** If a ref has no releases at all, the error message reads `no releases: no tag matches <pattern> in this ref's history`.

## Who is affected

- **A client querying `changes` for a declared, unreleased package.** It now receives matching dated entries with a note instead of an `unknown package` error.
- **A user running atlas in an environment without typescript installed.** atlas no longer downloads typescript in the background; typescript must be installed explicitly.
- **Everyone else.** No action needed.

## Details

- atlas searches for `node_modules/typescript` in two places:
  1. The target project directory (`from`).
  2. atlas's own installation directory (`own`).
- When querying `changes` with a package name that has no recorded releases on the active ref:
  - Calling `changes {"package": "<name>"}` returns `{ package, note, entries }`.
  - Calling `changes {"package": "<name>", "from": "...", "to": "..."}` returns JSON-RPC error `-32602` explaining that no version exists to window by.
- A repository ref with no tags matching `tagPattern` fails early with `-32602` and message `no releases: no tag matches <pattern> in this ref's history`.
