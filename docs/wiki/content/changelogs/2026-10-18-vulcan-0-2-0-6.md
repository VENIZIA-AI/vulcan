# Changelog - 2026-10-18

## typescript is never auto-installed, changes knows an unreleased package

<Badge type="info" text="Bug Fix" />

**In one line.** atlas stops Bun from auto-fetching typescript, and `changes` answers for declared packages that have no release on the current ref.

## What changed

- **atlas never auto-installs typescript.** It searches for `node_modules/typescript` in the project, then in atlas's own install, and installs nothing. If it is in neither, atlas fails with `atlas: cannot find typescript (looked in <project> and in atlas's own install) - install it with \`bun add typescript\``.
- **`changes` answers for a declared package with no releases on the current ref, when another package served by the same server has one.** It returns the dated entries whose frontmatter names the package, with the note `no release of <package> is recorded on this ref`. Passing `from` or `to` for it is refused with code `-32602`. Undeclared names still return `unknown package`.
- **Accurate reason when a ref has no releases.** The error reads `no releases: no tag matches <pattern> in this ref's history`.

## Who is affected

- **A client querying `changes` for a declared, unreleased package.** It now gets entries with a note instead of `unknown package`.
- **A user running atlas without typescript installed.** Install it explicitly.
- **Everyone else.** No action needed.
