# Changelog - 2026-10-18

## VULCAN 0.2.0-9: remote-host guard gaps closed

<Badge type="danger" text="Security" /> <Badge type="info" text="Bug Fix" />

**In one line.** The remote-host guard now asks in the places it used to let a command through, and passes trusted Docker endpoints.

## What changed

- **HTTP clients ask for a `readOnly` host.** `curl`, `wget`, `http`, `https`, `xh`, `httpie` and `xhs` prompt when the URL names a `readOnly` host; a URL on the open internet still passes.
- **Piped, fed and bare shells ask.** `| sh`, `| bash`, `bash <<<`, `sh -s`, a bare `bash` and `bash < file` prompt, because their input cannot be checked.
- **Nested and keyword commands are parsed.** The remote command of an `ssh` is inspected (`ssh lab1 "ssh prod1 id"` prompts unless the nested target is trusted), and so are commands after `do`, `then`, `else`, `elif`, `if`, `while`, `until`, `!`, `{` and `coproc`.
- **Trusted Docker and kubectl pass.** `docker -H ssh://lab1` (or `--host`) passes when the host is trusted, while `--context` still asks. A trusted host running `kubectl` or `docker` on its own default context passes.
- **The `readOnly` prompt names allowed commands**, such as `kubectl get|describe|logs|top`.

## Who is affected

- **A project with `remoteHosts`.** Upgrade and run `vulcan sync`. A `readOnly` entry matches a whole name: list `prod1.*` for `prod1.corp.example`.
- **Everyone else.** No action needed.
