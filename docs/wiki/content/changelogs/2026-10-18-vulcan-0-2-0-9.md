# Changelog - 2026-10-18

## Remote-host guard gaps closed

<Badge type="danger" text="Security" /> <Badge type="info" text="Bug Fix" />

**In one line.** The command guard tightens remote host checks across HTTP clients, piped shells, shell keywords, and nested SSH calls while fixing trusted Docker endpoints.

## What changed

- **HTTP clients ask when targeting a `readOnly` host.** `curl`, `wget`, `http`, `https`, `xh`, `httpie`, and `xhs` prompt when the URL names a `readOnly` host. A URL on the open internet still passes.
- **Piped or fed shells ask.** Commands using `| sh`, `| bash`, `bash <<<`, or `sh -s` prompt because piped input cannot be statically verified.
- **Bare shells and redirected shells ask.** A bare `bash`, or `bash < file`, asks because a shell with no script reads its input.
- **Remote commands in `ssh` are parsed.** The remote command of an `ssh` invocation is inspected, so commands like `ssh lab1 "ssh prod1 id"` prompt unless the nested target is trusted.
- **Commands after shell keywords are parsed.** Commands following `do`, `then`, `else`, `elif`, `if`, `while`, `until`, `!`, `{`, and `coproc` are inspected rather than treating the keyword as the command name.
- **Docker with remote daemon over SSH passes when trusted.** Running `docker -H ssh://lab1` (or `--host`) passes when the remote host is trusted, while `--context` still asks.
- **Trusted hosts running `kubectl` or `docker` on default context pass.** Ambient findings from nested SSH are dropped for a trusted host running `kubectl` or `docker` on its own default context.
- **The `readOnly` prompt names allowed commands.** The prompt explicitly names `kubectl get|describe|logs|top` as allowed read operations.

## Who is affected

- **A project with `remoteHosts`.** Upgrade and run `vulcan sync`. A `readOnly` entry matches a whole name: list `prod1.*` for `prod1.corp.example`.
- **Everyone else.** No action needed.
