# Changelog - 2026-10-18

## VULCAN 0.2.0-7: atlas help and tools, a doctor that checks the scaffold, init for workspaces

<Badge type="tip" text="New Feature" /> <Badge type="tip" text="Enhancement" /> <Badge type="info" text="Bug Fix" />

**In one line.** A new project, workspaces included, starts cleanly: atlas explains itself, `init` fits workspaces and `doctor` checks the scaffold.

## What changed

- **atlas prints its usage.** `vulcan x atlas --help`, `-h` and `help` print usage and exit 0; they used to wait silently on stdin.
- **`vulcan x atlas tools` lists the five tools** without an MCP client, and exits 2 with `nothing to serve` outside a project.
- **`init` skips root lint configs in a workspaces project.** When `package.json` declares `workspaces`, no root `.configs/{oxlint,eslint,oxfmt}` is written and `init` says `skipped`. A single-package project is unchanged.
- **`doctor` has a `scaffold` check.** It fails a workspaces project whose config lists no `packages`, and a knowledge index that still holds the `vulcan:scaffold` line `init` writes. Delete that line once the index describes the project.
- **Built-in renderers link only concepts that exist.** The "see also" line of `makefile-targets`, `source-map` and `binding-keys` appears once its concept exists, so a new project passes `okf check --strict`.
- **The `.mcp.json` hint fits every project**, and the adopting guide covers a fresh clone: run `install` as its own CI step, and `vulcan sync` before `vulcan doctor`.

## Who is affected

- **A workspaces project with no `packages` in its config.** `doctor` now fails `[scaffold]`: list them in release order.
- **A project that ran `init` on 0.2.0-7.** `doctor` fails `[scaffold]` until the index loses its marker line.
- **Everyone else.** No action needed: upgrade, then `vulcan sync`.
