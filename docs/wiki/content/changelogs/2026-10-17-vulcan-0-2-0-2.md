# Changelog - 2026-10-17

## VULCAN 0.2.0-2: the docs-update skill, symbols follow the build, skill evals

<Badge type="tip" text="New Feature" /> <Badge type="tip" text="Enhancement" /> <Badge type="info" text="Bug Fix" />

**In one line.** Every project gets a docs-update skill, atlas sees a rebuild without a restart, and the fixes IGNIS and ARDOR found while adopting 0.2.0-1 are in.

## What changed

- **`version` reads what runs.** A package the project only pins in `overrides` is read beside the package that depends on it first. A root `node_modules` link an older direct dependency left behind no longer wins.
- **Contents anchors as GitHub renders the heading.** Emphasis markers go (`The _first_ step` is `#the-first-step`), an underscore inside a word stays (`snake_case`), and entities are decoded (`Tom &amp; Jerry` is `#tom--jerry`).
- **Symbols follow the build.** In repo mode atlas fingerprints the packages' `.d.ts` and reads them again when a rebuild moves it: a changed signature shows up without restarting atlas (spec D2).
- **The server keeps its project's name.** It is `<project>-atlas` whenever atlas serves a project, whatever sources ride with it, so the name no longer changes with network state.
- **The okf README.** Describes renderers as project config and modules, not the old registries.
- **A new shipped skill, `docs-update`.** It updates the docs and the changelog after a code change, with every path read from the manifest, and runs the gates until they pass. `sync` links it.
- **Skill evals across models, in the VULCAN repo.** `make skill-evals SKILL=docs-writing PROJECT=../ignis` runs a skill's `evals/evals.json` on haiku, sonnet and opus, grades each run with opus and writes a report. A repo tool, not shipped to projects. It spends real model quota - run `make skill-evals-plan` first.

## Who is affected

- **A heading with emphasis or an entity in a long agent-read file.** Run `vulcan x okf gen` once.
- **Everyone else.** No action needed.
