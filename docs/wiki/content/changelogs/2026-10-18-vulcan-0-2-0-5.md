# Changelog - 2026-10-18

## VULCAN 0.2.0-5: many pages per renderer, coverage by resource, unique package keys

<Badge type="tip" text="New Feature" /> <Badge type="tip" text="Enhancement" /> <Badge type="info" text="Bug Fix" /> <Badge type="warning" text="Breaking Change" />

**In one line.** Three gaps BANA found while adopting VULCAN: one renderer for many pages, coverage for concepts that live elsewhere, and two packages in directories of the same name.

## What changed

- **A renderer may render many pages.** `render()` returns one file or an array of files, for example one page per entity. Every page is pre-rendered and checked in memory before anything is written (inside the bundle, one owner per path), `check` compares each page, and `coverage` reports the renderer as generated when every page has a concept. A single object still works.
- **Coverage counts a concept by its `resource`.** A directory an `okf.coverage` axis matches is covered by a concept at `/<axis>/<directory>.md`, or by any concept whose frontmatter `resource` is that directory's path from the root, wherever the concept lives. This applies to `okf coverage` and `okf check --strict`.
- **A repeated package key is an error.** `packages[].dir` is a unique key, not the directory name. A repeated `dir` fails the config with "dir is a unique key, not the directory name", a repeated npm `name` with "name 'X' is used twice", and two live packages at one `path` with "path 'P' is used twice". Two packages in directories both called `core` are `umbras-core` and `kits-core`, told apart by `path`.
- **A tag's `<dir>` may hold slashes.** With `atlas.tagPattern: '<dir>/<version>'`, atlas reads `apps/core/0.0.1-0` as directory `apps/core`, resolving through an alias of the package. The same holds for `atlas.releaseCommit`. However, `vulcan doctor`'s tag check still only accepts directories without a slash (`[a-z0-9][a-z0-9.-]*`), so doctor cannot read such tags.
- **CI runs on `ubuntu-26.04`** in three workflows in VULCAN's own repository (a repository change, not a package change).

## Who is affected

- **A project that lists the same `dir`, `name` or live `path` twice.** Its config now fails; give each package its own `dir` and set `path`.
- **Everyone else.** No action needed: upgrade, then `vulcan sync`.

## Breaking changes

> [!WARNING]
> A repeated package `dir`, `name`, or live `path` fails config validation.

**Before:**

```typescript
// .configs/vulcan.config.ts
packages: [
  { dir: 'core', name: '@bana/umbras-core', path: 'umbras/core' },
  { dir: 'core', name: '@bana/kits-core', path: 'auroras/kits/core' },
]
```

**After:**

```typescript
// .configs/vulcan.config.ts
packages: [
  { dir: 'umbras-core', name: '@bana/umbras-core', path: 'umbras/core' },
  { dir: 'kits-core', name: '@bana/kits-core', path: 'auroras/kits/core' },
]
```
