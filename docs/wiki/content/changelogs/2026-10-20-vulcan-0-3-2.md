# Changelog - 2026-10-20

## VULCAN 0.3.2: the generated manifest is protected

<Badge type="tip" text="Enhancement" />

**In one line.** `.agents/vulcan.manifest.json` is rendered from the config by `vulcan sync`; an agent can no longer edit it by hand, and `doctor` tells you how to fix one that was edited.

## What changed

- **A hook refuses writes to the manifest.** `guard-manifest` denies `Write`, `Edit`, `MultiEdit` and `NotebookEdit` on the file, and a Bash command that redirects into it, pipes to `tee`, edits it with `sed -i`, copies or moves onto it, or removes it. The message says to edit `.configs/vulcan.config.*` and run `vulcan sync`. Reading the file and `vulcan sync` itself still work. See [Hooks](/references/hooks/).
- **The manifest starts with a `$generated` note.** The first key reads `by vulcan sync from .configs/vulcan.config.* - do not edit`. atlas and the other readers ignore it. `schemaVersion` stays `1`.
- **`doctor` explains a stale manifest.** The `manifest` check now says the file is generated or edited by hand, and to edit `.configs/vulcan.config.*` and run `vulcan sync`.

## Who is affected

- **A project with a manifest written before 0.3.2.** No action needed. The file has no `$generated` key and `doctor` still accepts it; the next `vulcan sync` adds the key.
- **A project that edits the manifest by hand.** Edit `.configs/vulcan.config.*` instead and run `vulcan sync`.
- **A project that runs `vulcan sync` after upgrading.** The new hook is added to `.claude/settings.json`.

## Details

- The hook denies instead of asking, unlike `guard-writes`. It does not see what a script writes; it checks the tool call and the shell command.
- `doctor` compares the manifest with the one the config renders, ignoring the `$generated` key on both sides.
