# Changelog - 2026-10-23

## VULCAN 0.3.12: `bun fmt` formats the project, `bunfig.toml` `[fmt]` replaces the oxfmt config

<Badge type="warning" text="Behaviour change" />

**In one line.** The root `bunfig.toml` is the formatter's only configuration, and `bun fmt` formats your code the way oxfmt did.

## What changed

- **`init` writes a `[fmt]` section** in the root `bunfig.toml`: `printWidth = 100`, `singleQuote = true`, `arrowParens = "avoid"` (the shared style) and `flavor = "oxfmt"`. Everything else is Bun's default, so `bun fmt` produces the same files oxfmt did. An existing `bunfig.toml` is still kept byte for byte.
- **`flavor = "oxfmt"` keeps the output.** Without oxfmt in `package.json`, `bun fmt` formats like Prettier: a union type's first member moves to its own `|` line, for one. Measured on VULCAN, that changed 7 files; with the key, none.
- **`init` no longer writes `.configs/formatters/oxfmt.config.mts`**, and no longer installs `oxfmt`. A single-package project gets `oxlint`, `oxlint-tsgolint`, `eslint` and `@venizia/dev-configs`.
- **`doctor`'s `style` check** expects lint configs only (`oxlint` and `eslint` under `.configs/lints/`).
- **`doctor` warns** (exit code stays `0`, check `format`) when the root has no `bunfig.toml`, no `[fmt]` section, or a `[fmt]` without the flavor; when a `package.json` defines a `fmt` script, which `bun fmt` runs instead of formatting; when an `oxfmt.config.*` is left in `.configs/formatters/` (nothing reads it); and when `.oxfmtrc.json`, `.oxfmtrc.jsonc` or `oxfmt.config.ts` sits in the root or a package folder, which `bun fmt` loads by itself and which overrides `[fmt]`. See [doctor: format](../references/commands/doctor#format).
- **The `bunfig.toml` comment is accurate.** `bun fmt` inherits a parent folder's `bunfig.toml`, so `[fmt]` at the root applies to every folder below it; the generated comment says so. `init` writes only the root file, and `doctor` warns about a `[fmt]` section in a package or app folder (the root is the one decider).
- **Bun 1.4.4 or newer.** `engines` of all three packages and `.bun-version` say `>=1.4.4` / `1.4.4`; `bun fmt` arrived in that release.
- **`package.json` is sorted.** `bun fmt` sorts the keys of a `package.json` (`name`, `version`, ... `scripts`, then `dependencies` A to Z). Every manifest VULCAN writes comes out sorted: the root manifest and the app and library manifests of `init --preset`, and the root manifest `add --app` and `add --lib` rewrite. They go through `bun fmt` themselves, so `bun fmt --check` is green right after `init` and `add`. Nothing else VULCAN does writes a manifest's keys.
- **Every type `bun fmt` supports, except Markdown.** The lint scope is code, JSON, YAML, CSS, HTML and Vue: `"**/*.{ts,mts,tsx,js,mjs,json,jsonc,yml,yaml,css,html,vue}"`, the same list in IGNIS, ARDOR and VULCAN. Markdown stays out for now: `bun fmt` pads table columns, which grows the shipped rule tables about three times. `package.json` is JSON, so it is covered.
- **Generated files are already formatted.** The manifest `.agents/vulcan.manifest.json`, atlas's symbols lock, `atlas releases` and `atlas symbols` output go through `bun fmt` themselves, so regenerating never turns `make lint` red. The apps block of a generated `vulcan.config.mts` is JSON read back by `add`, so it carries `// prettier-ignore`; an existing project gets the line the next time `add` rewrites the block.
- **VULCAN formats itself with `bun fmt`.** The package `lint` and `fmt` targets run `bun fmt --no-script` with that glob and every line of `.configs/formatters/.ignore` as `--ignore-pattern`, because `bun fmt` does not read that file. New root targets `lint-files` and `fmt-files` (in `lint-all` and `fmt`) cover every file outside `packages/`: `.github`, `.agents`, `.configs`, `docs`, `scripts`. VULCAN's own `oxfmt.config.mts` files and `oxfmt` are gone from the repository.

## Who is affected

- **New projects.** Nothing to do; the section is in the file `init` writes.
- **Existing projects.** `doctor` warns until the root `bunfig.toml` has the `[fmt]` section above (`bun fmt --init` adds a commented one). To switch: add the four lines, delete `.configs/formatters/oxfmt.config.*`, drop `oxfmt` from `package.json`, run `bun fmt` with the glob above and check `git diff` shows only layout changes. Always pass the glob: a bare `bun fmt` also formats Markdown, JSON and YAML.
- **Framework presets** that still write an oxfmt config into an app get the leftover warning until they stop.
- **A project that keeps `oxfmt` and its config** keeps working: the warning says the config is unused (or, for the names `bun fmt` finds by itself, that it overrides `[fmt]`).
