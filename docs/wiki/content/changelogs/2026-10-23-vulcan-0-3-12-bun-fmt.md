# Changelog - 2026-10-23

## VULCAN 0.3.12: `bun fmt` formats the project, `bunfig.toml` `[fmt]` replaces the oxfmt config

<Badge type="warning" text="Behavior Change" />

**In one line.** The root `bunfig.toml` is the formatter's only configuration, and `bun fmt` formats your code the way oxfmt did.

## What changed

- **`init` writes a `[fmt]` section** in the root `bunfig.toml`: `printWidth = 100`, `singleQuote = true`, `arrowParens = "avoid"` and `flavor = "oxfmt"`. Without the flavor, `bun fmt` formats like Prettier and changes the layout of some files. An existing `bunfig.toml` is still kept byte for byte.
- **`init` no longer writes `.configs/formatters/oxfmt.config.mts`** and no longer installs `oxfmt`.
- **`doctor` warns** (exit code stays `0`, check `format`) about a missing `bunfig.toml`, `[fmt]` section or flavor; a `fmt` script in `package.json`; a leftover `oxfmt.config.*` in `.configs/formatters/`; an `.oxfmtrc.json`, `.oxfmtrc.jsonc` or `oxfmt.config.ts` that overrides `[fmt]`; and a `[fmt]` in a package or app folder. See [doctor: format](../references/commands/doctor#format).
- **Bun 1.4.4 or newer.** `engines` of all three packages say `>=1.4.4`; `bun fmt` arrived in that release.
- **Manifests come out sorted.** Every `package.json` VULCAN writes goes through `bun fmt`, so `bun fmt --check` is green right after `init` and `add`.

## Who is affected

- **New projects.** Nothing to do; the section is in the file `init` writes.
- **Existing projects.** `doctor` warns until the root `bunfig.toml` has the `[fmt]` section (`bun fmt --init` adds a commented one). To switch: add the four lines above, delete `.configs/formatters/oxfmt.config.*`, drop `oxfmt` from `package.json`, run `bun fmt "**/*.{ts,mts,tsx,js,mjs,json,jsonc,yml,yaml,css,html,vue}"` and check `git diff` shows only layout changes. Always pass the glob: a bare `bun fmt` also formats Markdown, JSON and YAML.
- **A project that keeps `oxfmt` and its config** keeps working: the warning says the config is unused.
