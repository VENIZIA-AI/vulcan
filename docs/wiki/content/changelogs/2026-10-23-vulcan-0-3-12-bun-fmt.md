# Changelog - 2026-10-23

## VULCAN 0.3.12: `bun fmt` formats the project, `init` writes the `[fmt]` section

<Badge type="info" text="Improvement" />

**In one line.** `bun fmt` formats your code the way oxfmt did, because the root `bunfig.toml` now carries the same settings.

## What changed

- **`init` writes a `[fmt]` section** in the root `bunfig.toml`: `printWidth = 100`, `singleQuote = true`, `arrowParens = "avoid"`. These are the settings of `oxfmtConfigs` in `@venizia/dev-configs`; the other options are Bun's defaults, so `bun fmt` and oxfmt produce the same files. An existing `bunfig.toml` is still kept byte for byte.
- **`doctor` warns** (exit code stays `0`) when the root has no `bunfig.toml` or no `[fmt]` section in it, and when a `package.json` defines a `fmt` script, which `bun fmt` runs instead of formatting. See [doctor: format](../references/commands/doctor#format).
- **Bun 1.4.4 or newer.** `engines` of all three packages and `.bun-version` say `>=1.4.4` / `1.4.4`; `bun fmt` arrived in that release.
- **VULCAN formats itself with `bun fmt`.** The package `lint` and `fmt` targets and the `scripts/` targets run `bun fmt` with the code glob (`"**/*.{ts,mts,js,mjs}"`) and every line of `.configs/formatters/.ignore` as `--ignore-pattern`, because `bun fmt` does not read that file. Measured on okf, atlas, cli and `scripts/`: the same files, no differences against oxfmt.

## Who is affected

- **New projects.** Nothing to do; the section is in the file `init` writes.
- **Existing projects.** `doctor` prints a warning until the root `bunfig.toml` has a `[fmt]` section; `bun fmt --init` adds a commented one, then set the three values above. Run `bun fmt` with the code glob, not bare: a bare `bun fmt` also formats Markdown, JSON and YAML.
- **Nothing is removed.** oxfmt, its template and the `style` checks stay; dropping them is a later, breaking step.
