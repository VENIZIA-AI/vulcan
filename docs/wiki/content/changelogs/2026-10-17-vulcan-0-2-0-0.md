# Changelog - 2026-10-17

## VULCAN 0.2.0-0: the project contract, atlas reads other projects, hooks fail closed

<Badge type="warning" text="Breaking Change" /> <Badge type="tip" text="New Feature" /> <Badge type="danger" text="Security" />

**In one line.** A project describes itself once in `.configs/vulcan.config.ts`, `vulcan sync` commits that description as a data manifest, and atlas serves any project that has one - its own and the ones it builds on.

## What changed

- **One config for everything.** `packages` (npm names, paths, aliases, retired packages), `knowledge.syncAreas`, the whole `okf` section, `atlas.sources` and `digest` live in the config. okf and atlas carry no project's names.
- **The project manifest.** `vulcan sync` writes `.agents/vulcan.manifest.json`, data only, and you commit it. atlas reads the manifest, never the config and never the project's code.
- **Package identity is the npm name.** Tables, tool answers and changelogs name `@venizia/ignis-kernel`. A directory or an alias still works as input.
- **Changelogs declare their packages.** `packages: [npm names]` in each entry's frontmatter; `vulcan x atlas changelogs migrate` writes it. `okf check --strict` checks it.
- **Releases from tags, symbols from `.d.ts`.** atlas computes releases from git tags and reads symbols from the built or installed `.d.ts`. `reference/releases.json` and `symbols.json` leave the project.
- **atlas serves other projects.** `atlas.sources` or `--source owner/repo@ref`: a cached git partial clone, an offline fallback, a GitHub tarball when git is missing. See the [atlas guide](/guides/core-concepts/atlas).
- **atlas ships code only.** No packaged IGNIS corpus, no snapshot mode. With nothing to serve it exits 2 and says how to get a source.
- **Shipped hooks fail closed.** A hook that cannot run (no `node_modules`, no bun) exits 2, so the write guard blocks instead of letting every Bash call through. A bare `bun install` still passes.
- **`vulcan sync --prune`.** Removes old VULCAN and plugin-era hook commands and dead skill links, never your own hooks. `doctor` reports what it would remove.
- **Rule integrity.** A `V-` ID in your rules must name a live base rule. After an upgrade, sync prints each base rule that was added, changed or removed.
- **Concepts that name code.** A concept's `symbols:` are locked by signature with `vulcan x atlas concepts stamp`; `concepts check` fails when one is gone or changed.
- **Project modules can extend okf.** Projects export renderers using `defineRenderer` from `@venizia/vulcan/okf` and register them in `okf.renderers[].module`.
- **Three new doctor checks.** `manifest`, `tags` and `prune` run in `vulcan doctor`.
- **CLI commands replaced by make targets.** `vulcan x atlas symbols gen|check` and `vulcan x atlas releases gen|check` exit 2 with "gone in 0.2.0-0" - scripts that call them must use the make targets.
- **Smaller fixes.** Skill links survive upgrades, `vulcan.mk` targets carry descriptions, the session digest reads bold rows and a minimap block, `<command> --help` prints help, and an unknown argument is an error.
- **Releases no longer wait for npm.** The release run ends once it tags. A fresh version can take minutes to download; confirm with `npm view @venizia/vulcan versions`.

## Who is affected

- **Existing consumer projects (IGNIS, ARDOR, BANA).** Impacted. Must complete migration steps for configuration, changelogs, manifest, and make targets, then run `vulcan sync --prune`.
- **CI pipelines calling deprecated atlas commands or make targets.** Impacted. Must update old `symbols-*` or `releases-*` invocations to the new make targets.
- **Projects serving or reading dependencies through atlas.** Impacted. Target projects must upgrade to VULCAN 0.2.0-0 and commit `.agents/vulcan.manifest.json`.

## Breaking changes

> [!WARNING]
> Upgrading from 0.1.0-x requires manual migration to the unified project contract, updated make targets, and declared changelog packages.

See the adoption guide at [/guides/get-started/adopt-vulcan](/guides/get-started/adopt-vulcan). Migration steps:

1. Declare all packages under the `packages` key in `.configs/vulcan.config.ts`, including npm names, directory paths, and aliases.
2. Run `vulcan sync` to generate and commit `.agents/vulcan.manifest.json`.
3. Run `vulcan x atlas changelogs migrate` to add frontmatter `packages: [...]` declarations across all changelog entries.
4. Replace retired make targets `symbols-gen`, `symbols-check`, `releases-gen`, and `releases-check` with `atlas-symbols` and `atlas-releases`.
5. Run `vulcan sync --prune` to remove stale hook commands and dead skill symlinks.

## Details

- Configuration keys consolidated into `.configs/vulcan.config.ts`: `packages`, `knowledge.syncAreas`, `okf`, `atlas.sources`, and `digest.oftenDropped`.
- Deprecated CLI commands `vulcan x atlas symbols gen|check` and `vulcan x atlas releases gen|check` exit 2 with "gone in 0.2.0-0".

| Name                                                                                    | Kind    | Meaning                                                                     |
| --------------------------------------------------------------------------------------- | ------- | --------------------------------------------------------------------------- |
| `packages`                                                                              | config  | Every package in release order: `dir`, `name`, `path`, `aliases`, `retired` |
| `atlas.sources`                                                                         | config  | Other projects atlas serves: `name`, `repo`, `ref`                          |
| `digest.oftenDropped`                                                                   | config  | The rule IDs the session digest repeats                                     |
| `vulcan sync --prune [--dry-run]`                                                       | command | Removes stale hook commands and dead skill links                            |
| `vulcan x atlas changelogs migrate [--dry-run]`                                         | command | Writes `packages:` into changelog entries                                   |
| `vulcan x atlas pull [--source <name>]`                                                 | command | Fetches sources now                                                         |
| `vulcan x atlas concepts stamp\|check`                                                  | command | Locks and checks the symbols concepts name                                  |
| `make atlas-symbols`, `atlas-releases`, `changelogs-migrate`, `knowledge-symbols-check` | make    | Replace `symbols-gen\|check` and `releases-gen\|check`                      |
