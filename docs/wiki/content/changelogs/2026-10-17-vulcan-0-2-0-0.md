# Changelog - 2026-10-17

## VULCAN 0.2.0-0: the project contract, atlas reads other projects, hooks fail closed

<Badge type="warning" text="Breaking Change" /> <Badge type="tip" text="New Feature" /> <Badge type="danger" text="Security" />

**In one line.** A project describes itself once in `.configs/vulcan.config.ts`, `vulcan sync` commits that description as a data manifest, and atlas serves any project that has one - its own and the ones it builds on.

## What changed

- **One config, one manifest.** `packages` (npm names, paths, aliases, retired packages), `knowledge.syncAreas`, the `okf` section, `atlas.sources` and `digest` live in the config. `vulcan sync` writes `.agents/vulcan.manifest.json`, data only; commit it. Package identity is the npm name; a directory or an alias still works as input.
- **atlas serves other projects.** Use `atlas.sources` or `--source owner/repo@ref` (see the [atlas guide](/guides/core-concepts/atlas)). Releases come from git tags and symbols from `.d.ts`. atlas ships code only; with nothing to serve it exits 2 and says how to get a source.
- **Shipped hooks fail closed.** A hook that cannot run (no `node_modules`, no bun) exits 2, so the write guard blocks instead of letting every Bash call through. A bare `bun install` still passes.
- **New commands.** `vulcan sync --prune` removes old VULCAN hook commands and dead skill links, never your own hooks. `vulcan x atlas concepts stamp|check` locks the symbols a concept names. `vulcan x atlas changelogs migrate` writes `packages:` into changelog entries.
- **Rule integrity.** A `V-` ID in your rules must name a live base rule; sync prints each base rule added, changed or removed.
- **More.** Project modules can extend okf with `defineRenderer`; `doctor` gains `manifest`, `tags` and `prune` checks.
- **Releases no longer wait for npm.** A fresh version can take minutes to install; confirm with `npm view @venizia/vulcan versions`.
- **Help and bad arguments.** `<command> --help` prints help, and an unknown argument is an error.

## Who is affected

- **Existing consumers (IGNIS, ARDOR, BANA).** Complete the steps below.
- **CI calling the old atlas commands or make targets.** Switch to the new make targets.
- **A project another project reads through atlas.** Upgrade to 0.2.0-0 and commit `.agents/vulcan.manifest.json`.

## Breaking changes

> [!WARNING]
> Upgrading from 0.1.0-x requires manual migration to the project contract, new make targets and declared changelog packages. See the [adoption guide](/guides/get-started/adopt-vulcan).

1. Declare all packages under `packages` in `.configs/vulcan.config.ts`: npm names, directory paths, aliases.
2. Run `vulcan sync` and commit `.agents/vulcan.manifest.json`.
3. Run `vulcan x atlas changelogs migrate` to add `packages: [...]` to every changelog entry; `okf check --strict` fails an entry without `packages:`.
4. `vulcan x atlas symbols gen|check` and `releases gen|check` now exit 2 with "gone in 0.2.0-0". Replace the make targets `symbols-gen`, `symbols-check`, `releases-gen` and `releases-check` with `atlas-symbols` and `atlas-releases`.
5. Run `vulcan sync --prune`.
