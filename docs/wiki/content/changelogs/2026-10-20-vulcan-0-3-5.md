# Changelog - 2026-10-20

## VULCAN 0.3.5: Agents Reach for atlas on Their Own

<Badge type="tip" text="Enhancement" />

**In one line.** An agent in a VULCAN project is now told when to call each atlas tool, so it looks facts up instead of answering from memory.

## What changed

- **The server sends `instructions`.** They name the corpora, say to call `symbol` before writing code that imports one of their packages, `search` then `get` when the user asks how something works, and `version` or `changes` for a release. Before, a project that read only its own repository sent none.
- **Tool descriptions open with their trigger.** `search`, `get`, `symbol`, `version` and `changes` say when to use them; `name` and `inputSchema` are unchanged.
- **The session-start digest has an "Atlas" block.** It appears only when the project's `.mcp.json` runs the atlas server.
- **A new base rule, `V-P-07`.** Facts about the framework and the project's own packages come from atlas, not memory. It is first in the default `digest.oftenDropped` list.

## Who is affected

- **Every project that runs the atlas server.** After `bun update @venizia/vulcan` and a new session the agent has the instructions. Run `vulcan sync` to refresh the manifest.
- **A project that sets its own `digest.oftenDropped`.** `V-P-07` is not added to your list; the "Atlas" block still appears.
