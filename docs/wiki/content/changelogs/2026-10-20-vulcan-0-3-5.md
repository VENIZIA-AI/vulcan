# Changelog - 2026-10-20

## VULCAN 0.3.5: agents reach for atlas on their own

<Badge type="tip" text="Enhancement" />

**In one line.** An agent in a VULCAN project used to see a generic MCP server with tools called `search`, `get` and `symbol` and no cue for when to use them, so it answered from memory unless the user mentioned atlas; now it is told when to call each tool, in four places, all rendered from the project's config.

## What changed

- **The server sends `instructions`.** The reply to `initialize` names the corpora (the project and every `atlas.sources` entry), says to call `symbol` for each export before writing code that imports one of their packages, `search` and then `get` when the user asks how something works, `version` or `changes` for a release, and not to answer from memory what atlas can answer. The lines that say how each source was reached follow, as before. Before this, a project that read only its own repository sent no `instructions` at all.
- **Tool descriptions open with their trigger.** `symbol`: "Before you import or call an export of `<projects>`, get its real signature, import path and source line here". `search`, `version` and `changes` follow the same shape, and `get` says to read a hit before relying on it. The original description still follows. The project names are filled in when the server starts.
- **The session-start digest has an "Atlas" block.** Three lines naming the corpora and the one-line rule. It appears only when the project's `.mcp.json` runs the atlas server.
- **A new base rule, `V-P-07`.** Facts about the framework and the project's own packages come from atlas, not memory. It is in the default `digest.oftenDropped` list, first, so the digest repeats it.

## Who is affected

- **Every project that runs the atlas server.** No config change and nothing to run: after `bun update @venizia/vulcan` and a new session, the agent has the instructions and the descriptions. Run `vulcan sync` to refresh the manifest, which lists the rule hashes.
- **A project that sets its own `digest.oftenDropped`.** The list is yours, so `V-P-07` is not added to it. The "Atlas" block of the digest still appears.
- **A client that reads `tools/list`.** The `description` of `search`, `get`, `symbol`, `version` and `changes` is longer; `name` and `inputSchema` are unchanged.

## Details

- Measured on a fresh `init --preset ignis` project with twelve headless Claude sessions (six prompts, two models) whose prompts never mention atlas: 4 of 12 called an atlas tool before answering or writing before this change, 12 of 12 after it. The per-session tool calls are in the pull request.
- The base rules are now 38: `V-P-07` is the seventh process rule.
