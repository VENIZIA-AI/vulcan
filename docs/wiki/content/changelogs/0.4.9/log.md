This release adds an agent event log with a board page, a commit-message check, CI that runs only the affected packages and a third preset kind. It gives `vulcan visualize` a new look, makes atlas connect at once on a cold start, and removes the repairs for files and spellings that only much older versions wrote, along with a make target and a few exported names. Run `vulcan upgrade`, then read the Breaking section for what your project calls. Pinning back to 0.4.8 later: its strict config refuses the keys this release added (`theme`, `board`, `commit`, `ci`, `events`, `local`, the object form of `guard.writes.trustedScripts`, and the `shared` and `presetKind` of a recorded preset), so remove them first.

## Breaking
- **The agent-setup make target is gone** `make-agent-setup-target-removed` (`@venizia/vulcan`): `base/make/vulcan.mk` no longer defines `agent-setup`, the older name of `vulcan-sync`. A script, CI step or README that calls `make agent-setup` now fails with `No rule to make target`; call `make vulcan-sync` or `bun x --no-install vulcan sync`. `vulcan doctor` now tells a fresh clone to run `make vulcan-sync`.
- **Three atlas exports moved into classes** `atlas-exports-in-classes` (`@venizia/vulcan-atlas`): `officialIdOf` is `OfficialPresets.idOf`, `triggerOf` is `SkillCatalog.triggerOf` and `skillCatalogOf` is `SkillCatalog.catalogOf`. Options and results are the same, and no alias is left. Code that imports an old name from `@venizia/vulcan-atlas` must change the import and the call.
- **Three okf exports moved into classes** `okf-exports-in-classes` (`@venizia/vulcan-okf`): `checkBundle` is `BundleConformance.check`, `splitFrontmatter` is `OkfFrontmatter.split` and `parseYamlMapping` is `OkfFrontmatter.parseMapping`. Options and results are the same, and no alias is left. `defineRenderer` and the renderer types are unchanged.
- **Unused version and mode exports are removed** `unused-version-and-mode-exports-removed` (`@venizia/vulcan-atlas`, `@venizia/vulcan-okf`): atlas no longer exports `ProtocolVersions`, `AtlasModes`, the type `TAtlasMode`, `AtlasCommands.CHANGELOGS` and `AtlasCommands.CONCEPTS`; `AtlasConstants.PROTOCOL_VERSION` is the one protocol version the server speaks. okf no longer exports `OkfVersions.V0_1`, `OkfVersions.SCHEME_SET` and `OkfVersions.isValid`; `OkfVersions.V0_2` and `OkfVersions.LATEST` stay. Nothing replaces them; the TypeScript check finds each use.
- **The config file must be a .mts** `config-file-must-be-mts` (`@venizia/vulcan`): `.configs/vulcan.config.mts` is the only spelling read. With a `.ts`, `.mjs` or `.js` config, `vulcan sync` and `vulcan doctor` print `no .configs/vulcan.config.mts found` and name the other file, and `vulcan x okf` fails with `no project config`. Rename the file to `.mts`. `vulcan init --config <ts|mjs|js>` is gone and fails with `unknown argument '--config'`; `init` always writes the `.mts`, and the starter templates for the other spellings are no longer shipped. A project that has an `.mts` beside another spelling no longer gets `more than one config`: the `.mts` is read and the other file is ignored.
- **The package placeholder in a tag template is gone** `tag-template-package-placeholder-removed` (`@venizia/vulcan`, `@venizia/vulcan-atlas`, `@venizia/vulcan-okf`): `<package>` was a synonym of `<dir>` in `atlas.tagPattern` and `atlas.legacyTagPatterns`. It is now plain text, so atlas looks for tags that contain the literal `<package>` and finds no releases. Replace `<package>` with `<dir>`.
- **A package name with capital letters is refused** `package-names-must-be-lower-case` (`@venizia/vulcan`, `@venizia/vulcan-atlas`): a `packages[].name` such as `@Venizia/kernel` was accepted; the config schema now stops `vulcan sync` and `vulcan doctor` with `is not an npm package name`, and atlas refuses a manifest that holds one. Fix the `name` in `.configs/vulcan.config.mts` and run `vulcan sync`.
- **vulcan add refuses an apps block with no presets list** `add-needs-presets-list-in-apps-block` (`@venizia/vulcan`): a `vulcan:apps` block written by an older version had no `presets` list and was repaired on `add`. Now `add` stops with `the vulcan:apps block ... is not the JSON vulcan wrote` and changes nothing. Add `presets: []` to the block and `presets: apps.presets,` under `packages: apps.packages,` in the config, then run `add` again.
- **vulcan sync --prune is gone** `sync-prune-removed` (`@venizia/vulcan`): the flag removed hook commands of 0.1.x and 0.2.0-0 and dead skill links. It now fails with `unknown argument '--prune'`, and `vulcan doctor` no longer has a `[prune]` check. Remove the flag from scripts, and delete a stale hook entry from `.claude/settings.json` by hand.
- **Old atlas subcommands and make targets are gone** `atlas-old-subcommands-and-make-targets-removed` (`@venizia/vulcan-atlas`, `@venizia/vulcan`): `vulcan x atlas changelogs migrate` and `vulcan x atlas concepts stamp|check` exit 2 with `unknown subcommand`, and the make targets `changelogs-migrate` and `knowledge-symbols-check` are gone from `base/make/vulcan.mk`. Add `packages:` to a changelog entry by hand. A `symbols:` key in a concept and a `.symbols.lock.json` file are ignored; delete the file.
- **atlas answers only the newest protocol version** `atlas-protocol-version-fixed` (`@venizia/vulcan-atlas`): `initialize` always answers `2025-06-18`. It used to echo `2025-03-26` or `2024-11-05` when a client asked for one of them. A client that speaks only an older version has to be updated.
- **A visualize spec with no `language` follows your profile** `visualize-language-follows-profile` (`@venizia/vulcan`): a spec that sets no `language` was always rendered in English; it now takes the reply language of your profile (`vi` gives Vietnamese words and `lang="vi"`), and English only when the profile has none. A page you build again, or a test that compares its text, changes with it. Set `language: 'en'` in the spec to keep English. A spec that built before still builds: the new markup check reads the page, not the spec, and the https-only link rule was already in force.
- **VULCAN cleans the safe part of .agents/local once a day** `local-folder-auto-clean` (`@venizia/vulcan`): at most once a day per project, the session-start hook starts a clean that removes `tmp/` entries older than a day (never one that holds a repository), `com.google.Chrome.*` and `org.chromium.Chromium.*` folders older than an hour, event files past the limits, and `release-candidates/` folders whose version is tagged. It never touches a worktree or a clone, and the next session prints one line when something was removed. Move anything you want to keep out of `tmp/` into `reports/`. `local: { autoClean: false }` turns it off, or `VULCAN_AUTO_CLEAN=off` for one shell.
- **doctor and atlas no longer repair state that only old versions wrote** `old-state-not-repaired` (`@venizia/vulcan`, `@venizia/vulcan-atlas`): `vulcan doctor` no longer warns about a git-tracked `.mcp.json` or a lint config left directly in `.configs/`, and a manifest written before `$generated` existed is reported as stale (run `vulcan sync`). A leftover `.agents/local/last-reply.json` is no longer deleted, and okf no longer skips a `.turbo` folder when it scans. A preset package in the 0.3.9 shape is refused with the usual `ships no VULCAN preset` message. An atlas cache set with no `format` file, or another one, is no longer served offline: it is rebuilt when online and the source is reported unavailable offline; delete `.agents/local/cache/atlas` to drop old sets.

## Added
- **A log of what your coding agents did** `agent-event-log` (`@venizia/vulcan`): `vulcan event add` writes one line to an append-only log in `.agents/local/events/<day>.jsonl` and `vulcan event tail` reads it. With `events: { log: true }`, `vulcan sync` installs the Claude Code hooks that write it for you. `events.dir` sends the lines of several repositories to one absolute folder. A line holds labels, never a message body, and secret-shaped text becomes `[redacted]`. When the log is on, `maxAgeDays` (30), `maxFiles` (30) and `maxSize` (`50MB`) remove old day files, never today's, and `vulcan clean --events` follows the same limits. Off by default; a project that sets nothing writes no log.
- **A board page of the flows your agents are working on** `board-page` (`@venizia/vulcan`): `vulcan board` reads the event log, and GitHub pull requests when `gh` can read them, and writes one read-only HTML page, by default `.agents/local/reports/board.html`, that shows each flow as Needs you, Blocked, Running, Parked or Done. `vulcan event add --kind decision --status approve|park|reject --flow F-n` records your answer. A `board` config key sets the owner, the title, a logo and a face for each agent. Without `gh`, or with `--no-github`, the page is built from the events alone.
- **A commit-message check against agent signatures** `commit-check` (`@venizia/vulcan`): `vulcan commit-check <message-file>`, `--text` and `--range <revs>` reject a `Co-Authored-By` or `Signed-off-by` trailer, or a `Generated with` line, that names an agent. With `commit: { message: { agent: { signature: 'deny' } } }`, `vulcan sync` installs the check as the `commit-msg` hook of each clone, never over a hook of yours, and writes Claude Code's `attribution` setting so it adds no signature. `commit.message.agent.names` and `allow` tune the list, and `commit.message.subject` takes your own subject pattern. Off until you turn it on; `vulcan doctor` warns when the hook is missing or out of date.
- **CI that runs only the affected packages** `ci-affected` (`@venizia/vulcan`): `vulcan ci affected --base <ref>` lists the workspace packages a change touches, the packages that depend on them and the checks each has (`typecheck`, `lint`, `test`, `compile`), as a list, with `--names` or with `--json`. A change to a lockfile, the root `package.json`, `bunfig.toml`, a root `tsconfig` file, `.configs/` or a workflow lists every package; `ci.affected.global` adds paths. `vulcan ci template github|gitlab` prints a workflow that uses it. The CI must fetch the full history. Nothing changes until you use it.
- **A preset can make a shared package** `shared-preset-kind` (`@venizia/vulcan`, `@venizia/vulcan-atlas`): a preset package may declare a `shared` kind next to `app` and `lib`, and `vulcan add --preset <name> --shared <name>` makes a package that depends on no framework, in the `layout.shared` folder. `vulcan preset diff <package>` now also works on a library or a shared package. A recorded preset gains an optional `shared` summary and a package entry an optional `presetKind` (`lib` or `shared`); a 0.4.8 `vulcan` refuses a config that holds either key, so upgrade first. The atlas `presets` tool accepts `kind: "shared"`, `@venizia/vulcan-atlas` exports `LibraryKinds` and `TLibraryKind`, and `IOfficialPreset` has an optional `shared` field. No official preset ships a shared kind yet.
- **A release script's read-only subcommands can run without an ask** `read-only-script-subcommands` (`@venizia/vulcan`): an entry of `guard.writes.trustedScripts` may be `{ script, readOnly: ['plan', 'registry'] }`. A call to that script whose first argument is a listed word skips the body check, and any other call still asks. The script must be tracked and equal to `HEAD`. `vulcan sync` writes these entries to the manifest, so run it after you add one.
- **vulcan visualize draws four more kinds and cites sources** `visualize-diagram-kinds` (`@venizia/vulcan`): `sequence`, `lifecycle`, `tree` and `compare` join the spec, and a `source` block (`repo`, a 40-character `commit`, `path`, `lines`) on a flow box, step or compare box is shown as `repo@commit:path:lines`. A `terms` list explains words your reader may not know. The size limits rose: the build warns at 80 KB and refuses at 150 KB.

## Changed
- **vulcan visualize pages have a new look and take your project colour** `visualize-new-look` (`@venizia/vulcan`): pages match the wiki style, with a top bar, a light and dark switch that the browser remembers, and cards that line up in a row. A `theme` config key (`accent`, optional `accentDark` and `accentText`) sets the colour, and `vulcan sync` writes it to the manifest; without it pages use a neutral slate. A page reads the reply language of your profile, or the `language` of its spec; English and Vietnamese are built in. Every colour is checked for contrast in both themes. Before a page is written its markup is checked: no request, no inline style or handler, and links only to `https` or to places on the page. Other existing specs render as before.
- **.agents/local has named folders, a warning for unknown entries and a wider clean** `local-folder-layout-and-clean` (`@venizia/vulcan`): `events/` and `release-candidates/` join the layout, and `vulcan sync` creates neither. `vulcan doctor` warns about each entry directly under `.agents/local` that is not part of the layout, with its size, and about release candidates whose version is tagged; it never deletes. `vulcan clean --events` and `--release-candidates` take those folders by name and are never part of `--all`. `vulcan clean --tmp` also takes browser leftovers. A worktree is also kept when its branch has no commit of its own or when it holds an ignored file a build cannot make again, such as `.env`, and one merged into `origin/develop` or the default branch of origin is taken.
- **Agents write fewer comments** `rule-v-c-09-lasting-comments` (`@venizia/vulcan`): rule `V-C-09` says a comment holds only a lasting fact the code cannot show, in one to three lines, and may be a short JSDoc on an export. Agents remove meaningless comments in the lines they touch. The rule is now in the default `digest.oftenDropped` list, so every session start prints it; a project with its own list adds `V-C-09`. `vulcan sync` prints `changed V-C-09`: commit the manifest.
- **Agents stop adding unused isValid methods** `rule-v-c-08-reworded` (`@venizia/vulcan`): rule `V-C-08` now says a const class of enumerable strings carries `SCHEME_SET` and `isValid` when something validates against it, and needs neither otherwise. Agents read the rule from `node_modules/@venizia/vulcan/base/rules.md`; `vulcan sync` prints `changed V-C-08`. No code has to change.
- **Synced skills write changelog entries for users only** `changelog-entries-for-users-only` (`@venizia/vulcan`): `docs-update`, `build-a-feature`, `docs-writing`, `ship` and `plan-a-change` say an entry is written only for a change that affects the users of a published package, with a plain title and no product name or version, and short. `visualize-work` lists the new kinds, the `theme` rule and the size limits. A project that keeps its own changelog will see its agents write entries differently after `vulcan sync`.
- **The retro skill records a rejection in the issue or pull request** `retro-rejection-in-issue` (`@venizia/vulcan`): a proposal the owner rejected is noted where it was rejected, with the reasons and what would reopen it; agents no longer write a file in `.agents/out-of-scope/`. A project with that folder can move what it wants to keep into the issues and delete the folder; nothing reads it. Run `vulcan sync` for the new skill text.
- **bun check counts as a gate run** `bun-check-counts-as-gate` (`@venizia/vulcan`): the session signals that tell an agent whether a gate ran treat `bun check` like `bun test`.
- **A session started without the launch file says so** `launch-file-warning` (`@venizia/vulcan`): when the project has `.agents/local/claude.launch.settings.json` and a Claude Code session runs without `CLAUDE_CODE_TMPDIR` in the project, the session digest opens with a Launch warning that prints `claude --settings .agents/local/claude.launch.settings.json` and tells the agent to say so in its first reply. Other agents and projects without the launch file get no warning.
- **sync asks which agents you use and keeps a hand-written CLAUDE.md** `sync-agent-choice-and-claude-md` (`@venizia/vulcan`): on a machine with no stored agent choice, no `--agents` flag and no `agents` list in the config, `vulcan sync` asks in a terminal whatever files the project has; without a terminal it writes the Claude files and stores nothing. A `CLAUDE.md` that is a symlink to an existing file, or the template `bun init` writes, is reported as skipped instead of replaced; delete it and sync again. Run `vulcan agents add <agent>`, or list `agents` in the config, to skip the question.

## Fixed
- **atlas connects at once on a cold start** `atlas-answers-on-cold-start` (`@venizia/vulcan-atlas`): `vulcan x atlas mcp` used to fetch and index every source before it answered; with three sources and an empty cache that took 42 seconds, longer than the 30 seconds Claude Code waits, so atlas did not connect. `initialize` and `tools/list` now answer at once and each source is indexed in a process of its own, so the same three sources are ready after about 19 seconds. A `search`, `get`, `symbol`, `version` or `changes` call waits up to 20 seconds for a source still being indexed, then answers from the ready ones with a `notServed` field that lists the sources still indexing, those that failed and why. A source that takes over ten minutes is stopped and reported. New settings: `VULCAN_ATLAS_CALL_WAIT_SECONDS` (20), `VULCAN_ATLAS_INDEX_JOBS` and `VULCAN_ATLAS_INDEX_TIMEOUT_SECONDS` (600), and `vulcan x atlas pull --warm` fetches and indexes only what the cache lacks. Restart your sessions; nothing has to be configured.
- **A pull that waits for another pull no longer fails** `atlas-pull-waits-for-lock` (`@venizia/vulcan-atlas`): when the pull holding the lock finished just as a second one read the age of `pull.lock`, the second stopped with a file-not-found error. A lock that has just gone now counts as free. This affects several atlas servers or pulls on one cache at once.
- **vulcan add accepts the catalog that init wrote from the same preset** `add-accepts-catalog-from-preset` (`@venizia/vulcan`): a second `vulcan add --preset` into the same monorepo no longer fails the `peers` check when the catalog pins exactly the version the preset lists for that package, as happens with a preset built on prerelease versions. Any other pin is checked as before.
- **guard-outside reads $PWD from the call** `guard-outside-reads-pwd-from-call` (`@venizia/vulcan`): `$PWD` and `${PWD}` in a path come from the working directory of the call, and after a `cd` from the new folder, not from the hook's own environment. `export TMPDIR=$PWD/../x` is judged by the folder it lands in: inside the project it passes, outside it asks. A loop of symlinks no longer recurses without end.
- **guard-writes trusts a listed script by the file the shell runs** `guard-writes-trusts-file-shell-runs` (`@venizia/vulcan`): a `trustedScripts` entry covers the file the shell opens, with links followed, not the file a path names after the hook folds `..` as text. After `cd`, `pushd` or `popd`, a relative script word is not covered by any entry, so a call such as `cd scripts && bun release.ts plan` gets the normal script check; use the path from the project root, or no `cd`.
