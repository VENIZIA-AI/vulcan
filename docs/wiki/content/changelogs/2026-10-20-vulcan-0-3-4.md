# Changelog - 2026-10-20

## VULCAN 0.3.4: a preset can declare the imports of its app

<Badge type="tip" text="New Feature" />

**In one line.** A preset can set the `imports` field of the app's `package.json`, so apps can use Node subpath imports (`#src/...`) without `tsconfig` `paths`, `tsc-alias` or a Vite alias.

## What changed

- **A new optional preset key, `imports`.** It is an object of strings, for example `{ "#src/*.json": "./src/*.json", "#src/*": "./src/*.js" }`. `presetVersion` stays `1`.
- **`init` and `add` write it into the app.** The app's `package.json` gets `imports` after `private`, with the values exactly as the preset wrote them. The `{{project}}` and `{{app}}` tokens are not replaced in it.
- **A key without `#` is refused.** The preset is rejected before anything is written, and the message names the key: `imports.src/* "src/*" is not a subpath import: a key starts with #`.
- **No key, no field.** A preset without `imports` leaves the app's `package.json` as before. See [Presets](/references/presets).

## Who is affected

- **Framework authors.** A preset that needs subpath imports can declare them. It should require VULCAN 0.3.4 or later: VULCAN 0.3.3 and older ignore the key and write an app without `imports`.
- **Everyone else.** No action needed; presets that do not declare `imports` produce the same app as before.

## Details

- Only string values are accepted. A conditions object (`{ "node": "...", "default": "..." }`) is refused with the key named by the schema error.
