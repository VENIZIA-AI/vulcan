# Changelog - 2026-10-17

## VULCAN 0.1.0-2: no IGNIS framework dependency, V-C-02 caps parameters at 5

**Type:** Breaking Change

**In one line.** Installing VULCAN no longer pulls in `@venizia/ignis-helpers`, and the options-object
rule now allows a second parameter where one object cannot carry it, up to 5.

## What changed

- **No IGNIS framework dependency.** `@venizia/vulcan`, `vulcan-okf` and `vulcan-atlas` depend on no
  `@venizia/ignis-*` package. Installing VULCAN no longer adds a second `ignis-helpers` next to IGNIS's
  own, or pins ARDOR and BANA to an IGNIS release.
- **V-C-02 reworded.** One options object first, at most 5 parameters: fold every argument you can into
  the first object; a second parameter only where that object cannot carry it (a repository method
  taking its data and its query options separately).
- **Releases wait for npm.** A release run passes only once npm serves every package's tarball, so a
  version is installable the moment the run is green.

## Who is affected

- **Projects citing V-C-02.** The rule is looser at the edges: a second parameter is allowed where
  needed, never more than 5. Code that already uses one options object needs no change.
- **Everyone else.** No action needed.

## Details

- Lint enforcement of the 5-parameter cap (`venizia/max-params-own`) comes with the
  `@venizia/dev-configs` release that ships `houseConfigs`; until then V-C-02 is a reviewed rule.
