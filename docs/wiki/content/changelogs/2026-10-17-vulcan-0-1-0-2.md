# Changelog - 2026-10-17

## VULCAN 0.1.0-2: no IGNIS framework dependency, V-C-02 caps parameters at 5

<Badge type="tip" text="Enhancement" />

**In one line.** Installing VULCAN no longer pulls in `@venizia/ignis-helpers`, and the options-object rule allows a second parameter where one object cannot carry it, capped at 5.

## What changed

- **No IGNIS framework dependency.** Neither `@venizia/vulcan`, `@venizia/vulcan-atlas`, nor `@venizia/vulcan-okf` depends on an `@venizia/ignis-*` package. `@venizia/ignis-helpers` was removed from `dependencies` in `@venizia/vulcan` and `@venizia/vulcan-atlas`, from `devDependencies` in `@venizia/vulcan-okf`, and from the root catalog. Installing VULCAN no longer pulls in a duplicate helper package or pins downstream projects to an IGNIS release.
- **V-C-02 reworded.** One options object first, at most 5 parameters: fold every argument you can into the first object; a second parameter is allowed where that object cannot carry it (such as a repository method taking data and query options separately).
- **Repository release workflow waits for npm.** In the repository release workflow, a read-back step waits until every tarball returns 200 from npm, so a version is installable the moment the run succeeds.

## Who is affected

- **Projects citing V-C-02.** The rule is looser: a second parameter is allowed where needed, up to 5. Code already adhering to one options object needs no change. No action needed.
- **Everyone else.** No action needed.

## Details

- Lint enforcement of the 5-parameter cap (`venizia/max-params-own`) comes with the `@venizia/dev-configs` release that ships `houseConfigs`; until then V-C-02 is a reviewed rule.
