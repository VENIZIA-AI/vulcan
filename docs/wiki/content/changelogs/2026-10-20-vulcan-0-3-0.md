# Changelog - 2026-10-20

## VULCAN 0.3.0: one command creates a monorepo

<Badge type="warning" text="Breaking Change" /> <Badge type="tip" text="New Feature" /> <Badge type="tip" text="Enhancement" />

**In one line.** `vulcan init --preset <name>` creates a monorepo with its first app, `vulcan add` adds more apps, and `init` on an existing project no longer leaves tasks for you to find.

## What changed

- **`vulcan init --preset <name>` creates a monorepo.** It asks for names in a terminal or takes them from flags, copies the framework app template, installs, syncs, and runs the checks. See [vulcan init](/references/commands/init#create-a-monorepo-with-preset).
- **`vulcan add --preset <name>` adds an app.** Add a second backend, or a frontend that proxies `/api` to a backend. See [vulcan add](/references/commands/add).
- **A framework ships its template as a preset.** The layout and format are documented in [Presets](/references/presets).
- **`init` without `--preset` requires `package.json`.** When the folder has no `package.json`, `init` exits 1 with `run 'bun init' first, or use --preset`.
- **`init` exits 1 when its install fails.** In earlier versions it always exited 0.
- **`init` writes `.gitignore`.** In 0.2.0 `init` only printed a hint; 0.3.0 writes it with status `updated`. `CLAUDE.md`, `CLAUDE.*.md`, `.claude/` and `.agents/plans` are added when missing. Lines already present stay.
- **`init` installs the lint tools it configures.** In a project without workspaces, `init` runs `bun add -d --exact` for `oxlint`, `oxlint-tsgolint`, `oxfmt`, `eslint` and `@venizia/dev-configs`. In a workspaces root, it installs only `@venizia/dev-configs`.
- **`init` writes `.configs/vulcan.config.mts`.** The default extension was `ts`. An existing `.ts`, `.mjs` or `.js` config keeps loading, and `--config ts` still writes `.ts`.
- **`layout` joins the config, and `doctor` gains an `apps` check.** `layout` names the folders for backend, frontend and shared code. The check fails when a `layout` folder is not a workspace or a package sits outside them. A project without `layout` is not checked.
- **`upgrade` is stable by default.** It installs the `latest` tag. `--nightly` installs the higher of `latest` and `next`. A version or tag you name wins over both. `upgrade` refuses `--stable` together with `--nightly`, and prints a note when the installed version is a prerelease.
- **`sync` replaces the `CLAUDE.md` that `bun init` writes.** The file holds only Bun's tips, so it becomes `@AGENTS.md`. A `CLAUDE.md` you wrote is left alone.
- **`init` recognises an atlas server under any name.** An `.mcp.json` entry whose arguments run `atlas mcp` counts, whatever the key.
- **Atlas updates its missing package error message.** The error for a missing live package folder now says `.configs/vulcan.config.*` instead of `.ts`.
- **`init` ends with a numbered list of what is left.** It includes the `vulcan:scaffold` line and any `add` hint.
- **The wiki ships at vulcan.venizia.ai.** The site hosts guides, references and changelogs published with GitHub Pages.

## Who is affected

- **A project configuring an atlas key listed in Breaking changes.** Delete the key.
- **A project running `vulcan upgrade` to follow the prerelease line.** Add `--nightly`. Without it, `upgrade` stays on the stable release.
- **A project with a `.ts` config.** No action needed. Rename the file to `.mts` when you want the new default.
- **A new project.** Use `init --preset`. Existing projects can ignore it.
- **Everyone else.** Run `bun x --no-install vulcan upgrade 0.3.0`, then `vulcan doctor`.

## Breaking changes

> [!WARNING]
> Affects projects configuring `atlas.releaseCommit`, `atlas.typescriptFrom`, or `atlas.legacyTagPrefixes` because no tool reads them.

**Before:**

```typescript
// .configs/vulcan.config.mts
export default defineConfig({
  atlas: {
    releaseCommit: '[#<issue>] chore(<dir>): release v<version>',
    typescriptFrom: 'packages/*/src',
    legacyTagPrefixes: ['v'],
  },
});
```

**After:**

```typescript
// .configs/vulcan.config.mts
export default defineConfig({
  atlas: {},
});
```

1. Delete `atlas.releaseCommit`, `atlas.typescriptFrom`, and `atlas.legacyTagPrefixes` from `.configs/vulcan.config.*`. If set, the config fails with `atlas.<key> was removed - no tool reads it; delete it from the config`.

## Details

- Presets and monorepo creation live in `packages/cli/src/create/`.
- Config `layout` and the `doctor apps` check live in `packages/cli/src/config/` and `packages/cli/src/doctor/`.
- Upgrade mode logic lives in `packages/cli/src/commands/`.
