# Changelog - 2026-10-20

## VULCAN 0.3.0: one command creates a monorepo

**Type:** Breaking Change, Feature, Enhancement

**In one line.** `vulcan init --preset <name>` creates a monorepo with its first app, `vulcan add` adds more apps, and `init` on an existing project no longer leaves five things for you to find.

## Breaking

- **`atlas.releaseCommit`, `atlas.typescriptFrom` and `atlas.legacyTagPrefixes` are removed.** No tool read them. A config that still sets one now fails with `atlas.<key> was removed - no tool reads it; delete it from the config`. Delete the key from `.configs/vulcan.config.*`.

## What changed

- **`vulcan init --preset <name>` creates a monorepo.** It asks for the names (or takes them from flags), copies the framework's app template, installs, syncs and runs the checks. See [vulcan init](/references/commands/init#create-a-monorepo-with-preset).
- **`vulcan add --preset <name>` adds an app.** A second backend, or a frontend that proxies `/api` to a backend. See [vulcan add](/references/commands/add).
- **A framework ships its template as a preset.** The format is in [Presets](/references/presets).
- **`layout` joins the config, and `doctor` gains an `apps` check.** `layout` names the folders for backend, frontend and shared code. The check fails when a `layout` folder is not a workspace or a package sits outside them. A project without `layout` is not checked.
- **`init` writes `.configs/vulcan.config.mts`.** The default extension was `ts`. An existing `.ts`, `.mjs` or `.js` config keeps loading, and `--config ts` still writes `.ts`.
- **`init` writes `.gitignore` entries.** `CLAUDE.md`, `CLAUDE.*.md`, `.claude/` and `.agents/plans` are added when missing. Lines already there stay.
- **`init` installs the lint tools it configures.** `oxlint`, `oxlint-tsgolint`, `oxfmt` and `eslint` are added with `bun add -d` unless declared. They were optional peers that Bun never installed.
- **`init` ends with a numbered list of what is left.** It includes the `vulcan:scaffold` line and any `add` hint.
- **`sync` replaces the `CLAUDE.md` that `bun init` writes.** The file holds only Bun's tips, so it becomes `@AGENTS.md`. A `CLAUDE.md` you wrote is left alone.
- **`init` recognises an atlas server under any name.** An `.mcp.json` entry whose arguments run `atlas mcp` counts, whatever the key.
- **`upgrade` is stable by default.** It installs the `latest` tag. `--nightly` installs the higher of `latest` and `next`. A version or tag you name wins over both.

## Who is affected

- **A project that sets an atlas key listed above.** Delete the key; see Breaking.
- **A project that runs `vulcan upgrade` to follow the prerelease line.** Add `--nightly`. Without it, `upgrade` now stays on the stable release.
- **A project with a `.ts` config.** No action needed. Rename the file to `.mts` when you want the new default.
- **A new project.** Use `init --preset`. Existing projects can ignore it.
- **Everyone else.** Run `bun x --no-install vulcan upgrade 0.3.0`, then `vulcan doctor`.
