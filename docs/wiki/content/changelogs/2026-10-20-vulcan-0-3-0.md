# Changelog - 2026-10-20

## VULCAN 0.3.0: Create a Monorepo With One Command

<Badge type="warning" text="Breaking Change" /> <Badge type="tip" text="New Feature" /> <Badge type="tip" text="Enhancement" />

**In one line.** `vulcan init --preset <name>` creates a monorepo with its first app, `vulcan add` adds more apps, and `init` on an existing project no longer leaves tasks for you to find.

## What changed

- **`vulcan init --preset <name>` creates a monorepo.** It asks for names in a terminal or takes them from flags, copies the framework app template, installs, syncs, and runs the checks. See [vulcan init](/references/commands/init#create-a-monorepo-with-preset).
- **`vulcan add --preset <name>` adds an app.** Add a second backend, or a frontend that proxies `/api` to a backend. See [vulcan add](/references/commands/add) and [Presets](/references/presets).
- **`init` fails loudly.** Without `--preset` it exits 1 with `run 'bun init' first, or use --preset` when there is no `package.json`, and it exits 1 when its install fails (it always exited 0 before). It ends with a numbered list of what is left.
- **`init` writes more for you.** It writes `.gitignore` (status `updated`, lines already present stay; it adds `CLAUDE.md`, `CLAUDE.*.md`, `.claude/` and `.agents/plans` when missing), installs the lint tools it configures, and writes `.configs/vulcan.config.mts`. An existing `.ts`, `.mjs` or `.js` config keeps loading, and `--config ts` still writes `.ts`.
- **The lint tools depend on workspaces.** Without workspaces `init` runs `bun add -d --exact` for `oxlint`, `oxlint-tsgolint`, `oxfmt`, `eslint` and `@venizia/dev-configs`; in a workspaces root it installs only `@venizia/dev-configs`.
- **`sync` replaces the `CLAUDE.md` that `bun init` writes.** The file holds only Bun's tips, so it becomes `@AGENTS.md`. A `CLAUDE.md` you wrote is left alone.
- **`layout` joins the config, and `doctor` gains an `apps` check.** `layout` names the folders for backend, frontend and shared code; a project without `layout` is not checked.
- **`upgrade` is stable by default.** It installs the `latest` tag. `--nightly` installs the higher of `latest` and `next`. A version or tag you name wins, and `--stable` with `--nightly` is refused.

## Who is affected

- **A project configuring a removed atlas key.** Delete the key (see Breaking changes).
- **A project running `vulcan upgrade` to follow the prerelease line.** Add `--nightly`.
- **Everyone else.** Run `bun x --no-install vulcan upgrade 0.3.0`, then `vulcan doctor`.

## Breaking changes

> [!WARNING]
> Affects projects configuring `atlas.releaseCommit`, `atlas.typescriptFrom`, or `atlas.legacyTagPrefixes` because no tool reads them.

**Before:**

```typescript
// .configs/vulcan.config.mts
export default defineConfig({
  atlas: {
    releaseCommit: '[#<issue>] chore(<dir>): release v<version>',
    typescriptFrom: 'packages/*/src',
    legacyTagPrefixes: ['v'],
  },
});
```

**After:**

```typescript
// .configs/vulcan.config.mts
export default defineConfig({
  atlas: {},
});
```

1. Delete `atlas.releaseCommit`, `atlas.typescriptFrom`, and `atlas.legacyTagPrefixes` from `.configs/vulcan.config.*`. If set, the config fails with `atlas.<key> was removed - no tool reads it; delete it from the config`.
