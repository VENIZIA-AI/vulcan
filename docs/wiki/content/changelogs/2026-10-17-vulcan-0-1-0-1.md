# Changelog - 2026-10-17

## VULCAN 0.1.0-1: Atlas reads the project's packages, two fixes

<Badge type="warning" text="Breaking Change" /> <Badge type="info" text="Bug Fix" />

**In one line.** `vulcan x atlas surface|symbols` walk the package directories your config lists instead of IGNIS's, and two tooling bugs are fixed.

```ts
// .configs/vulcan.config.ts
atlas: { packages: { kernel: '@venizia/ardor-kernel', ardor: '@venizia/ardor' } },
```

## What changed

- **Atlas package list.** `surface` and `symbols` read the keys of `atlas.packages` (the package directories) and stop with what to add when missing. The npm-name values are not read. For surface and symbols only, no project's names are built in.
- **`sync` keeps your key order.** A settings file that only needed reordering is no longer rewritten, so `doctor` agrees with a fresh sync.
- **`doctor` follows make includes.** A shipped target redefined in an included `make/*.mk` is reported, with the file that redefines it.
- **Base rules update.** Shipped alongside this release, base rules V-W-05, V-C-03, and V-C-05 are retired (IDs never reused), and V-C-18 and V-P-02 are reworded (see [base rules that fit every project](./2026-10-17-base-rules-fit-every-project)).

## Who is affected

- **A project running `surface` or `symbols`.** Add `atlas.packages` to `.configs/vulcan.config.ts`.
- **A project with an existing `.claude/settings.json`.** No action needed: one sync is now enough.
- **A project whose `make/*.mk` redefines a shipped target.** `doctor` now reports it - rename the project target.

## Breaking changes

> [!WARNING]
> Projects running `surface` or `symbols` without `atlas.packages` in their config stop with an error.

1. Add `atlas: { packages: { <dir>: '<npm name>', ... } }` to `.configs/vulcan.config.ts`, in release order.
2. Run `vulcan x atlas surface gen` and `symbols gen` once: the tables list exactly those packages.

## Details

- `releases` still carries IGNIS's package list (it includes retired directories so old changelogs keep their package); project config for it comes with retired-package support.
