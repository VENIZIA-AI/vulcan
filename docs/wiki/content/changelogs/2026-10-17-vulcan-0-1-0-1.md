# Changelog - 2026-10-17

## VULCAN 0.1.0-1: atlas reads the project's packages, two fixes

**Type:** Breaking Change, Bug Fix

**In one line.** `vulcan x atlas surface|symbols` walk the packages your config lists instead of
IGNIS's, and two bugs ARDOR's trial found are fixed. It also ships
[base rules that fit every project](./2026-10-17-base-rules-fit-every-project.md).

```ts
// .configs/vulcan.config.ts
atlas: { packages: { kernel: '@venizia/ardor-kernel', ardor: '@venizia/ardor' } },
```

## What changed

- **Atlas package list.** `surface` and `symbols` read `atlas.packages` (directory to npm name, in
  release order) and stop with what to add when it is missing. No project's names are built in.
- **`sync` keeps your key order.** A settings file that only needed reordering is no longer rewritten,
  so `doctor` agrees with a fresh sync.
- **`doctor` follows make includes.** A shipped target redefined in an included `make/*.mk` is
  reported, with the file that redefines it.

## Who is affected

- **A project running `surface` or `symbols`.** Add `atlas.packages`; IGNIS and ARDOR already have it.
- **A project with an existing `.claude/settings.json`.** No action needed: one sync is now enough.
- **A project whose `make/*.mk` redefines a shipped target.** `doctor` now reports it - rename the
  project target.

## Breaking changes

> **Warning:** `surface` and `symbols` stop without `atlas.packages`.

1. Add `atlas: { packages: { <dir>: '<npm name>', ... } }` to `.configs/vulcan.config.ts`, in release
   order.
2. Run `vulcan x atlas surface gen` and `symbols gen` once: the tables list exactly those packages.

## Details

- `releases` still carries IGNIS's package list (it includes retired directories so old changelogs
  keep their package); project config for it comes with retired-package support.
