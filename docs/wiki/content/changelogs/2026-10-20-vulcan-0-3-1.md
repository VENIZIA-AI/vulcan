# Changelog - 2026-10-20

## VULCAN 0.3.1: the first run has no snag

<Badge type="tip" text="Enhancement" /> <Badge type="info" text="Bug Fix" />

**In one line.** `init --preset` and `add --preset` end by telling you which URLs to open, and `add` no longer downloads a preset just to tell you a flag is missing.

## What changed

- **A preset can list the URLs to open.** The optional `urls` key holds paths such as `/api/hello`. `init` and `add` print one `open http://localhost:<port><path>` line per path. A preset without `urls` prints the root, as before. The format version stays `1`; see [Presets](/references/presets).
- **`add` ends with the same `Next:` block as `init`.** It prints `make dev`, then the URLs of the apps in the monorepo, the one just added at its own port. An app made before 0.3.1 has no recorded URLs and shows its root.
- **`add` checks flags before it downloads.** Without a terminal, a missing `--app`, a side folder that neither the flag nor `layout` gives, and a frontend with neither `--api` nor `--no-api` are reported first. The side is known from the flags (`--frontend-dir`, `--api` and `--no-api` mean a frontend); when they do not name it, the side checks wait for the download.
- **A new project ignores `*.tsbuildinfo`.** The root `.gitignore` that `init --preset` writes has the entry, so `tsconfig.tsbuildinfo` no longer shows as untracked after the checks.

## Who is affected

- **Preset authors.** Add `urls` when the app does not serve its root. 0.3.0 ignores the key, so nothing breaks.
- **Everyone else.** No action needed. Run `bun x --no-install vulcan upgrade 0.3.1` to get it.

## Details

- `init` records the preset's `urls` in the app's `package.json` under `vulcan.urls`, so a later `add` can list them.
- An app with no `*PORT=` line in its `.env.example` is left out of the `add` Next block.
- A test runs `init --preset` in a pseudo-terminal and answers the four prompts, so the terminal flow is covered as well as the flags.
