The guards that read a command line stop more hidden force-pushes and writes, ask less about plain data, ask instead of passing when they crash, and now run in Antigravity, Codex, omp and pi. A project can also list its own CLIs as trusted scripts. Update `@venizia/vulcan`; the parser fixes load from `node_modules`, and `vulcan sync` brings the new hook wrappers and the guard files of the agents you choose.

## Breaking
- **The guards ask when they crash or time out** `guards-ask-on-failure`: a `guard-git` or `guard-outside` hook that started and then crashed, was killed or (where `timeout` exists, so not on a stock macOS) ran past 30 seconds used to let the call through; it now asks. `guard-git` asks only about a command that names `git` or `gh`. A missing `node_modules/@venizia/vulcan` or `bun` still passes, with a note on stderr, so a fresh clone can run `bun install`. Run `vulcan sync` to get the new wrappers in `.claude/settings.json`; `vulcan doctor` reports the old ones as stale. When a hook cannot load (a module that fails to import, say), every `git` or `gh` command (and every `guard-outside` call) asks until you run `bun install`, or set `VULCAN_GUARDS=off` for the session. `guard-scripting`, which only advises, still passes. Codex cannot ask, so there a guard that crashes or times out is refused.
- **The guards now run in the agents your project lists** `guards-run-in-listed-agents` (`@venizia/vulcan`): a project whose `agents` (or, on a machine that has already synced, the choice stored in `.agents/vulcan.local.json`) names omp, pi, Antigravity or Codex gets a guard file for it on the next `vulcan sync` (`.omp/hooks/pre/vulcan-guards.ts`, `.pi/extensions/vulcan-guards.ts`, `.agents/hooks.json`, `.codex/hooks.json`), where nothing checked those agents before. A delete or force-push of `develop` or `main` is now denied there; any other force-push, `git reset --hard` and a `git branch -D` of an unmerged branch ask; a write outside the project asks; and the write guards run. Codex prints an ask as a deny, and omp and pi block an ask when no UI can answer it.

## Added
- **The guards run in Antigravity, Codex, omp and pi** `guards-in-more-agents`: Until now the guards ran in Claude Code only. `vulcan sync --agents <your list>` now writes a guard file that runs the same guard scripts: `.omp/hooks/pre/vulcan-guards.ts` for omp, `.pi/extensions/vulcan-guards.ts` for pi, `.agents/hooks.json` for Antigravity and `.codex/hooks.json` for Codex. `sync` owns each file, merges it with your own hooks, hides it from git on your machine and takes it back when you stop choosing the agent; a file of your own at that path, or one git tracks, is left alone. Pi loads project extensions only after you trust the project, and Codex runs the hook only after you review and trust it in `/hooks`. A project that already lists one of these agents is affected by the next `vulcan sync`: see the Breaking item `guards-run-in-listed-agents`.
  Codex and Cursor cannot ask on a tool call, so an `ask` is printed as a `deny` there. In Antigravity, `agy --dangerously-skip-permissions` approves an `ask`; a `deny` still holds. Cursor and Copilot read the Claude hooks of `.claude/settings.json`, and every decision now carries the fields they document.
  Checked with real runs in Claude Code, omp 18.8.9 and Antigravity 1.4.7; pi 1.4.0 only through its SDK with a scripted provider. Not verified: Codex, Cursor and Copilot (they follow their documentation and unit tests), the `ask` dialog in a real terminal in omp, pi and Antigravity, and Windows.
- **A project can list its own CLIs as trusted scripts** `trusted-scripts`: `guard.writes.trustedScripts` names repo-relative `.ts` scripts (no globs) whose body `guard-writes` does not read for mutating calls, so a project CLI no longer asks on every `bun <script>.ts` run. A script is trusted only while git tracks it and it equals the last commit; a modified, untracked or symlinked script, or a git that cannot answer, gets the normal check and the ask says why. The command line is still checked (`curl -X POST`, `kubectl apply`, `psql` ask as before), and the imports of a script are not read: this is not a sandbox. `vulcan doctor` reports each listed script and warns about a path that never takes effect. The list defaults to empty.
- **`vulcan add --lib --dir` says why a folder was not recorded in the layout** `add-lib-layout-note`: when the folder cannot be listed in `layout.shared` (uppercase, a dot, more than four segments, nested with a listed folder), the library is still created there and `add` prints one line with the reason, so the lost `guard-package` coverage is not silent.

## Changed
- **The write and remote-host guards stop asking about data** `guards-ask-less-about-data`: `guard-writes` and `guard-remote-hosts` read the command through the shared parser. A heredoc written to a file (`cat > docs/deploy.md <<EOF ... kubectl apply ... EOF`) and the arguments of read-only tools (`rg`, `grep`, `cat`, `ls`, `find` without `-exec` or `-delete`, and others) are data and no longer ask. A heredoc fed to a program that runs it (`bash <<EOF`, `ssh host <<EOF`, `psql <<EOF`) and a print piped into a shell still ask. On a corpus of 16 quiet shapes and 24 real ones, 12 of the 16 asked before and none after, and all 24 real ones still ask. The `/tmp` ask now names `.agents/local/tmp/<task>/`. No action needed; the hooks load from `node_modules`.

## Fixed
- **The hook wrappers no longer need `CLAUDE_PROJECT_DIR`** `hooks-without-project-dir`: every wrapper in `.claude/settings.json` falls back to the working directory (`${CLAUDE_PROJECT_DIR:-$PWD}`), so a host that reads this file without setting the variable no longer gets exit 2 on every call. Claude Code always sets the variable, so nothing changes there. Affects Cursor and Copilot, per their documentation (not run there); run `vulcan sync` to replace the old wrappers.

## Security
- **The guards read more spellings of a forbidden command** `guards-read-more-spellings`: these hid a force-push or a write from `guard-git` and the guards that read a command, and are now read as the command they are: `env -S "git push -f origin main"` and `--split-string` (with the options inside the value), `$'git' push -f origin main` (ANSI-C quoting, in every word), `xargs --eof git push -f origin main`, a backslash before a newline, a quote inside `$(...)` or a backtick, a quoted `<<`, a heredoc fed to a shell (`bash <<EOF` is read as commands, so a `git push -f` inside it is seen), and `watch 'git push -f origin main'`. In `guard-git` and `guard-outside`, a line over 100,000 characters, a parse that throws, or more than four `git` or `gh` queries for one line now ends in an ask instead of a crash or a pass (`guard-writes` and `guard-remote-hosts` read nothing from a line that long and do not ask), and the parser has a budget so a crafted line cannot make a guard run out of time. A variable (`X=git; $X push`) is still not read: the guards stop accidental and drifting commands and are not a sandbox, and the hooks page lists every bypass found so far. Affects every project that syncs VULCAN, from 0.4.1 (the release that shipped the guards) to 0.4.4. Update `@venizia/vulcan`; no `vulcan sync` is needed. What a guard now denies or asks about was never a supported workflow: to run such a command on purpose, hand the exact command to the owner or confirm the ask (Codex prints an ask as a deny).
