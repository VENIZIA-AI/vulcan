This release makes agents load the right skill more often, keeps their temporary files in the project, lets a project tell the guards about its own deploy and migrate commands, and lets a repository publish a signed prebuilt atlas index. Nothing breaks unless a project already has a make target named `wiki-links-check` or `wiki-anchors-check`, which now fails `vulcan doctor` until it is renamed. Update the packages, run `vulcan sync` and restart your agent sessions.

## Breaking
- **A make target of your own named `wiki-links-check` or `wiki-anchors-check` fails `vulcan doctor`** `wiki-link-target-name-taken` (`@venizia/vulcan`): `vulcan.mk` now defines both targets, and a shipped target cannot be redefined, so a project that already had a target of either name (a `Makefile` or an included `*.mk`) fails `vulcan doctor` after the upgrade and cannot run its own. Rename yours, or delete it and use the shipped one.

## Added
- **A project lists the deploy, migrate and push targets its guards ask about** `guard-project-targets` (`@venizia/vulcan`): `guard.writes.commands` is a list of `{ rule, what, pattern }` (`rule` is `V-W-02` or `V-W-03`, `pattern` a JavaScript regular expression, `ignoreCase: true` for the other spelling) and `guard.git.askPush` lists branch names, with `*` for any run of characters. `guard-writes` asks on a command that matches, and `guard-git` asks on a plain `git push` to a listed branch, also inside compound commands (`cd x && make deploy-y`, `bash -c "..."`, `sudo ...`) and never on text that is data (`echo "make deploy-x"`, a commit message). A force-push or a delete of `develop` or `main` is still denied. A pattern that does not compile, another rule or an odd branch name fails the config. Run `vulcan sync` and commit the manifest: it writes both lists into a `guard` block, only when set. `vulcan doctor` prints one note per listed command. The guards are a guard against drift, not a sandbox: a command that builds its name at run time is not seen. The manifest is read from the project root (`CLAUDE_PROJECT_DIR`, else the working directory), so in an agent other than Claude Code that starts a session in a subfolder the lists may not be found. A project that lists nothing changes nothing; the V-W-02 and V-W-03 rows now say what the hook covers, so `vulcan sync` reports the base rules as changed once.
- **A repository can publish a signed prebuilt atlas index** `signed-prebuilt-atlas-index` (`@venizia/vulcan-atlas`, `@venizia/vulcan`): `vulcan x atlas index --out <dir> [--key-env <name>] [--repo <owner/name>]` writes the gzipped index and a signed envelope of the HEAD commit (the private key comes from the environment variable `ATLAS_INDEX_KEY`, or the one `--key-env` names), `vulcan x atlas index keygen` makes the ed25519 key pair, `vulcan x atlas index publish` is what the action runs, and the action `VENIZIA-AI/vulcan/.github/actions/atlas-index` publishes the pair to the release `atlas-index` of the repository from CI. For a GitHub source whose manifest lists public keys (`atlas.index.keys`), atlas downloads the pair of the commit it resolved, checks the signature, commit, repository, format, digest and size, and installs it instead of building. Any failure prints one line with its reason and atlas builds locally as before; `--no-prebuilt` or `atlas.prebuilt: false` turns the download off. `vulcan sync` writes both keys to the manifest in an `atlas` block, only when set, and a key that is not the base64 of 32 bytes fails the config. A pair signed by a key the manifest does not list is not used, which is how a key is rotated, and the start notice says when an index was prebuilt (`index: prebuilt, built by atlas <version>`). A project that only reads sources needs nothing.
- **`vulcan visualize` pages cover more kinds of explanation** `visualize-more-kinds` (`@venizia/vulcan`): a state-coloured banner, key numbers as tiles, a minimap stepper and a card for what you need to do, plus the optional sections `comparison`, `ideaMap`, `explainer`, `architecture`, `timeline`, `findings` (with bar, line and donut charts) and `decisionRecord`. A slide mode (**Present**, or `?present=1`) shows one section at a time, and the layout fits a phone. Existing specs render as before in the new look; every new field is optional. The default heading of the `strip.next` card is now "What you need to do" (it was "What needs action"); a spec that sets `chrome.next` keeps its own. Run `vulcan sync` to get the updated skill and spec reference.
- **Two wiki link gates ship in `vulcan.mk`** `wiki-link-gates` (`@venizia/vulcan`): `make wiki-links-check` fails when the wiki or the knowledge bundle names a source path git does not track, and `make wiki-anchors-check` (after `make docs`) fails on a link to a heading or a page that does not exist. Set `WIKI_REPO := <owner>/<name>` before the `vulcan.mk` include. They are new targets, so nothing changes until you call them, unless your project already has a target of either name (see the Breaking item `wiki-link-target-name-taken`).

## Changed
- **Agent sessions keep temporary files in the project** `project-temp-folder` (`@venizia/vulcan`): in Claude Code the session-start hook exports `TMPDIR` as the project's `.agents/local/tmp`, so `mktemp` and the scripts a command starts stop writing to `/tmp` and stop causing permission prompts. `guard-outside` no longer asks about a bare `mktemp` there; a path chosen by hand (`mktemp /tmp/x.XXXX`, `TMPDIR=/tmp ...`) still asks. `vulcan sync` also writes `.agents/local/claude.launch.settings.json` (gitignored); start Claude Code with `claude --settings .agents/local/claude.launch.settings.json` to move its own task-output files and its MCP servers too. `vulcan doctor` warns when that file is missing or names another checkout. Agents other than Claude Code need `TMPDIR` in their own launch environment (`export TMPDIR=$PWD/.agents/local/tmp`).
- **Eight skill descriptions say when to load them and what to skip** `skill-descriptions` (`@venizia/vulcan`): `plan-a-change`, `ship`, `review-a-change`, `docs-writing`, `knowledge-sync`, `retro`, `visualize-work` and `report-back` now open with "Use when", name concrete situations, say what the skill makes and end with a short "Skip for" list. They were chosen by running each against the original on Sonnet and Haiku; the other four skills keep their text. The skills load from `node_modules`: update the package, run `vulcan sync` and restart sessions, because a running session keeps the descriptions it loaded. Your own skills are not affected. atlas builds its one-line skill list from the first sentence after "Use when", so those lines are a little longer.
- **A delegation brief names the skill instead of retyping it** `delegation-brief-names-skill` (`@venizia/vulcan`): `base/references/delegation-brief.md` gains item 3: when the work matches a skill, the brief names it and tells the receiver to load it. The later items move down by one. Run `vulcan sync` to get the new reference.
- **atlas builds a cached index again when its format changed** `atlas-index-format-rebuild` (`@venizia/vulcan-atlas`): each cached index now carries a `format` file, and an index of another format (a cache from before this release counts as older) is built again instead of being served. The first start after an upgrade that changes what an index holds builds each declared source's index again, once; no action is needed. Offline, atlas still serves the newest cache and the start notice says it is of another format. A project with no declared sources is not affected.
- **The package READMEs credit the logo and the licenses name Venizia Co., Ltd.** `readme-and-legal-name` (`@venizia/vulcan`, `@venizia/vulcan-atlas`, `@venizia/vulcan-okf`): the README of each package carries the VENIZIA logo credit with a link to venizia.ai, and `LICENSE.md` reads "Copyright (c) 2025 Venizia Co., Ltd." (it read "VENIZIA Ltd. Co."); the license itself, MIT, is unchanged. The `vulcan doctor` warning for a project without `flavor = "oxfmt"` in `[fmt]` now says "without it `bun fmt` uses its default style when oxfmt is not a dependency"; it still fires in the same case, and a test that compares the exact message must expect the new words.
